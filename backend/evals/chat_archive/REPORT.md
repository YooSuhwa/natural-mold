# 긴 대화 원문 보관 측정

2026년 11월 27일, 한국어 조사 대화 20개에서 두 저장 방식 모두 원문 복원에 성공했다. 조각 보관 방식에서 최대 RSS 중앙값은 26.28% 줄고 요약 시간 p95는 84.70% 늘었다. 메모리 기준인 20% 절감은 충족했고 지연 증가 허용치인 10%를 초과했다. 기존 단일 파일 저장을 기본으로 유지한다.

| 측정 항목 | 기존 단일 파일 | 조각 보관 |
|---|---:|---:|
| 복원 해시가 일치한 대화 | 20/20 | 20/20 |
| 프로세스 최대 RSS 중앙값 | 152.80 MiB | 112.64 MiB |
| 요약 시간 p95 | 33.10 ms | 61.13 ms |
| 복원한 20개 보관 기록의 총 바이트 | 80,694,415 | 77,927,625 |
| 기록·목록을 포함한 파일 크기 합계 | 80,694,415 | 77,978,044 |

## 재현 방법

저장소의 `backend`에서 실행한다. 한 모드만 확인할 때는 `--mode legacy` 또는 `--mode candidate`를 쓴다.

```sh
uv run --locked python -m evals.chat_archive.benchmark --mode both --output /tmp/moldy-chat-archive.json
```

- macOS arm64 한 호스트에서 Python 3.12.13, Deep Agents 0.7.42, LangGraph 1.2.24를 사용했다. 각 대화와 저장 방식마다 새 워커 프로세스와 임시 저장소를 열고, 어느 방식을 먼저 실행할지 대화마다 교대했다. 최종 측정에는 같은 소스 스냅샷을 사용했다.
- 주제는 지역 도서관 이용률, 하천 수질 관측 등을 포함한다. 대화 하나마다 4개 연도에 걸쳐 해마다 3회씩 질의하고, 한국어 질문, 도구 호출, 다국어 CSV 결과, 답변을 결정적으로 생성했다. 대화마다 48개 메시지 중 45개가 요약 대상이었다.
- 운영 코드의 `ScopedOffloadStorage`와 실제 비동기 요약 미들웨어를 호출했다. 가짜 모델은 고정된 요약 문장을 반환했다. 타이머는 입력 대화 구성을 끝낸 뒤 미들웨어 호출부터 상태 변경 반환까지를 측정한다. 이 값에는 문맥과 요약 프롬프트 처리, 파일 입출력, 로컬 모델 호출이 함께 포함된다. 공급자 네트워크 지연과 전체 채팅 응답 시간은 측정 범위 밖이다.
- p95는 방식별 80회 요약 시간에서 76번째 순서통계량이다. RSS는 복원 검증 전의 프로세스 전체 최대 상주 메모리를 기록한 뒤 20개 워커의 중앙값을 냈다. 파일 크기는 바이트 길이의 합이며 파일시스템 블록 할당량과는 별도다.
- 기존 파일에서는 매 실행마다 달라지는 시간 머리글을 분리하고, 보관된 역할·본문·도구 결과를 원래 메시지로 다시 만든 XML 구간과 대조했다. 새 방식은 각 원본 메시지를 JSON Lines로 직렬화해 순서, ID, 유형, 도구 메타데이터까지 복원 스트림의 SHA-256과 대조했다. 두 방식에 실제로 같은 원본을 넣었는지도 대화별 입력 해시로 확인했다.
- 같은 호스트에서 다른 작업이 함께 돌던 앞선 비교에서도 메모리는 26.26% 감소했고 p95는 337 ms에서 2,681 ms로 증가했다. 표에는 코드 스냅샷을 고정하고 다시 측정한 값을 실었다. 두 측정 모두 같은 기본값 결정을 뒷받침한다.

대화별 입력·복원 해시, 160회 개별 요약 시간, 워커별 RSS 및 파일 크기는 [측정 결과](results.json)에 있다. [고정 입력 생성기](corpus.py)와 [실행 코드](benchmark.py)로 재측정할 수 있다.
