# 목표 실행, 보충 지시와 산출물 검수

2026년 11월 27일, 가상 국내 업체 세 곳의 견적을 일반 채팅과 목표 채팅에 맡겼다. 각 방식에서 8건 중 4건이 원본과 일치하는 파일을 만들었다. 일반 채팅은 검수자가 후속 요청을 10번 보냈고, 목표 채팅은 워커가 10번 자동으로 이어갔다. 목표가 완료로 표시한 4건의 고정된 파일 버전을 내려받아 검사했을 때 오완료는 0건이었다. [과제와 독립 정답](cases.py) · [실행별 측정값](paired_observations.jsonl) · [집계](paired_summary.json)

## 같은 업무, 같은 횟수의 시도

양쪽에 가격과 출처까지 명시한 동일한 사용자 지시를 보냈다. 목표에는 사용자가 확인한 견적 세 행을 완료 조건으로도 등록했다. 일반 채팅의 검수자는 저장된 파일이 정답과 어긋나면 한 번 더 비교를 요청했다. 목표 워커는 같은 상황에서 후속 실행을 예약했다. 단일 조건에 진전이 없는 경우 두 방식 모두 세 번째 턴에서 멈췄다. 과제마다 실행 순서를 번갈아 배치했다.

| 8개 과제의 합계 | 일반 채팅 | 목표 채팅 |
|---|---:|---:|
| 정답 파일을 제출한 과제 | 4 | 4 |
| 끝까지 정답을 제출하지 못한 과제 | 4 | 4 |
| 실행 오류 | 0 | 0 |
| 수동 후속 요청 | 10 | 0 |
| 자동 후속 실행 | 0 | 10 |
| 워커 실행 / 모델 호출 | 18 / 27 | 18 / 27 |
| 입력 / 출력 토큰 단위 | 262,682 / 1,991 | 227,351 / 1,991 |
| 시험 단가로 환산한 전체 금액 | $0.266664 | $0.231333 |

정답과 행 순서만 바뀐 정답은 첫 턴에 통과했다. 잘못된 가격과 이전 분기 출처를 두 번째 턴에 고치는 과제는 각각 한 번의 후속 실행으로 통과했다. 가격을 끝까지 틀리거나 업체 사이에서 출처를 바꾼 표, 파일 누락, 빈 파일은 양쪽 모두 정답을 제출하지 못했다. 목표는 네 건 모두 진전 없음으로 차단했다. 모델은 36턴 모두 완료했다는 문장을 냈고 대화 이력에도 그 문장이 남았다. 몰디의 목표 완료는 산출물 검사 결과를 따랐다.

FastAPI 채팅 경로, 실제 Deep Agents 워커와 파일 도구, PostgreSQL 16, 사용량 저장소를 사용했다. 로컬 모델 대역은 두 방식에 동일한 오류와 수정 출력을 제공했다. 입력·출력 단위는 대역이 직렬화한 요청·응답에서 정규식으로 센 값이다. 워커가 받은 사용량과 DB 사용량을 대조했고, 입력 100만 단위당 1달러, 출력 100만 단위당 2달러로 환산했다. 이 표는 반복 가능한 시험의 사용량 차이를 보여준다. 실제 모델 호출 요금이나 서비스 전반의 절감률은 이 실험에서 측정하지 않았다. ## 잘못된 가격·출처를 완료로 판정하는지

별도 PostgreSQL 16.15에서 비소유자 역할과 테넌트 RLS를 적용했다. 등록한 기준 행, 실제 아티팩트 저장소, 종료된 실행에 대한 목표 판정, 완료 의도와 버전별 다운로드를 연결했다. 파일을 삭제하거나 바이트 수를 유지한 채 변조하는 시험은 임시 저장소 안에서 수행했다.

| 등록한 조건과 표본 | 결과 |
|---|---|
| 업체별 가격·출처가 있는 목표 14건 | 유효한 파일 2건 모두 완료. 내려받은 2건 중 오완료 **0/2** |
| 위 14건 중 필수 반례 12건 | 완료로 잘못 받아들인 반례 **0/12** |
| 구조만 지정한 대조군 2건 | 가격이 틀린 표와 출처가 틀린 표 모두 구조 검사를 통과. 사실 대조에서는 **0/2** |
| 열 전체에 정확한 출처 하나를 지정한 대조군 2건 | 정확한 URL 1건 통과. 경로의 대소문자가 다른 1건 거부 |

12개 반례는 잘못된 가격, 잘못된 출처, 두 업체의 출처 교환, URL 경로 대소문자 변경, 해외 업체, 업체 중복, 누락된 업체, 빈 가격 셀, 빈 파일, 파일 미생성, 저장 뒤 파일 삭제, 길이가 같은 바이트 변조다. 알려진 정답에 대한 시험이므로 모델도 입력에서 원본 견적을 읽을 수 있다. 외부 웹 문서의 사실성은 별도로 확인해야 한다. [문서별 판정과 버전 해시](document_results.json)

실제 모델에도 같은 가상 견적을 한 번 제공하고 CSV 본문만 요청했다. 지정된 라이브 테스트 프록시가 POST 1회, HTTP 200을 기록했고 입력 240·출력 92토큰이 반환됐다. 결과를 그대로 아티팩트 기록기에 전달해 파일 버전을 만들었다. 목표를 완료 처리한 뒤 그 버전을 다시 열어 공급자 응답의 SHA-256과 업체별 값·출처를 대조했다. 이 한 건은 위의 모의 비용 대조나 반례 12건의 분모에 넣지 않았다. ## 보충 지시가 모델에 도착하는 시간

일반 채팅 24개를 순차 실행하고 각 실행에서 시각 조회 도구가 대기하는 동안 보충 지시를 두 개씩 보냈다. 두 지시가 접수된 뒤 도구를 재개했다. 48건 모두 같은 실행의 다음 모델 입력에 올바른 도구 결과 뒤로 한 번씩 순서대로 들어갔고, DB의 지시 상태도 반영으로 바뀌었다.

| 측정 구간 | 중앙값 | p95 |
|---|---:|---:|
| 지시 접수 행 생성 → 해당 모델 입력 호출 | 90.983ms | 132.007ms |
| HTTP 접수 응답 → 해당 모델 입력 호출 | 89.205ms | 130.195ms |

첫 구간은 같은 호스트의 UTC 시각을 사용했다. 접수 행의 생성 시각은 트랜잭션 커밋보다 조금 이르다. 두 번째 구간은 단조 시계로 쟀다. p95는 오름차순 48개 중 46번째 값이다. 두 지시씩 하나의 모델 호출에 묶였고 모델은 결정적 로컬 구현을 사용했다. 실제 서비스의 지연은 도구 수행 시간, 작업 부하, 배포 환경에도 영향을 받는다. [실행별 측정값](steer_latency.json) · [모델 입력 관측 방법](measure_steers.py)

## 재현

백엔드 의존성과 PostgreSQL 16 실행 파일이 필요하다. 두 명령은 임시 PostgreSQL을 띄운 뒤 자신이 만든 데이터와 서버를 정리한다. 문서 시험은 저장한 실모델 응답을 오프라인으로 다시 읽는다. 일반·목표 비교는 루프백 모델 대역만 사용한다.

```bash
cd backend
uv run python -m evals.continuous_work.measure_documents --output /tmp/goal-documents.json --replay-model-output evals/continuous_work/live_quote.json
uv run python -m evals.continuous_work.worker_driver --output /tmp/goal-observations.jsonl
uv run python -m evals.continuous_work.summarize_pairs /tmp/goal-observations.jsonl --output /tmp/goal-summary.json
```

워커 실행 파일명은 새 경로를 사용한다. 보충 지시 시간 측정은 별도로 마이그레이션한 일회용 PostgreSQL과 격리된 환경에서 실행한다. 구동 옵션과 타이머 위치는 측정 코드의 설명에 있다. [지시 시간 측정기](measure_steers.py)
