# 기억 회상 평가 결과 (PR-B2, 2026-11-07)

사전 등록: `PREREGISTRATION.md`. 원자료: `results.json`(질문별 넣은 기억 포함), `dataset.json`.
재실행: `cd backend && .venv/bin/python -m evals.memory_recall.build && .venv/bin/python -m evals.memory_recall.run`
(LLM 응답은 `cache/llm`에 있어 다시 부르지 않는다. 벡터 캐시(3.7MB)는 저장소에 넣지 않으므로 처음 build 때 임베딩 16회를 부른다. 그 뒤 재실행은 호출 0회이고 결과는 결정적이다.)
모델: 사내 LiteLLM 게이트웨이. 기억 작성 `gpt-5.4-mini`, 질문 작성 `claude-sonnet-5`, 임베딩 `text-embedding-3-large`·`text-embedding-3-small`(1024차원).

## 데이터
- 가상 10명 × 기억 30~32개 = 306개, 질문 160개, 묶음 153개. 조정용 80 / 보고용 80.
- 보고용 범주별 n: 같은 단어 15, 조사 15, 바꿔 말하기 15, 시간 10, 여러 턴 10, 관련 없음 15.
- 기억 306개 모두 `write_memory`로 저장(거부·제안 0). 키워드는 접미사 목록 대비책(OpenSearch 없음).

## 결정
- **벡터 회상은 끈다.** 사전 등록 기준 "관련 없는 질문에 넣지 않음 ≥ 0.9"를 rrf가 0.87 [0.67, 1.00]로 넘지 못했다(같은 단어 1.00, 바꿔 말하기 0.73은 통과). `VECTOR_FLOORS`는 빈 채로 둔다. 다음 후보는 `text-embedding-3-large@1024` 코사인 0.40~0.42이며, 범주당 질문 25개 이상으로 다시 잰다. `text-embedding-3-small`은 바꿔 말하기가 0.27로 쓰지 않는다.
- **키워드 기준은 0.3을 유지한다.** 사전 등록 규칙은 0.5를 골랐지만, 조정용 분할에서 0.35~0.5가 모두 동점(같은 단어 1.0, 바꿔 말하기 0)이라 동점 규칙이 가장 큰 값을 고른 것이다. 0.5에서는 조사·시간·여러 턴이 무너진다. 0.3은 양쪽 분할에서 "넣지 않음" 기준을 지킨다(조정용 0.93, 보고용 1.00). 다음 평가의 목적 함수에는 조사·시간·여러 턴을 넣는다.
- **접미사 목록을 고쳤다(평가 뒤, 같은 데이터로 재실행).** 한 음절 명사 뒤의 두 음절 이상 조사("표에서"→"표", "칸으로"→"칸")를 떼고, 주제가 없는 질문 낱말(거·어떻게·어디·있나 등)과 요청 어미(해줄래요 등)를 뺐다.

## 지연
- 회상 계산(기억 30개, SQLite, 질의 벡터 캐시): p95 약 2ms. Postgres 기억 1,001개는 통합 시험에서 13ms.
- 질의 임베딩 1회(`text-embedding-3-large@1024`, 게이트웨이 20회): p50 502ms / p95 627ms. 회상 예산 300ms를 넘으므로 벡터를 켤 때는 임베딩을 실행 준비 초기에 시작하거나 예산을 따로 둔다.

## 한계
- 범주당 n=10~15라 구간이 넓다. 사람당 후보가 30개라 1,000개 규모의 순위 품질은 재지 않았다.
- 질문 작성자가 기억을 보고 썼으므로 같은 단어·조사 범주는 쉬운 편이다.
- 키워드는 접미사 목록만 쟀다(Nori는 미측정. Nori 분석 자체는 사내 망에서 동작과 지연 p95 3.1ms를 확인).
- 벡터를 켜면 넣는 양이 약 4배(54→199토큰)로 는다. 벡터만으로 걸린 후보의 상한을 다음 평가에서 잰다.
