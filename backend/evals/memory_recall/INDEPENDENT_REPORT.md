**로컬 Moss MiniLM 후보는 품질 기준을 통과하지 못했다.** 코사인 기준 0.42에서 키워드와 벡터를 결합하면 바꿔 말한 질문 25개 중 10개에서 정답을 찾았다. 키워드만 썼을 때는 0개였다. 그러나 벡터를 결합하면 무관 질문 25개 모두에 기억이 들어가 배제율 0.90 기준을 충족하지 못했다. [질문별 비교 결과와 실행 근거](local_moss_minilm_2026_11_27.json) · [평가 방법과 사전 지정한 후보](INDEPENDENT_PROTOCOL.md)

2026-11-27에 합성 사용자 5명의 승인된 기억 142개, 질문 150개를 사용했다. 사용자별로 같은 후보 기억을 검색하고 범위·토큰 예산까지 적용해 선택한 목록을 비교했다. 아래는 두 방식을 함께 측정한 실행의 점추정과 95% 신뢰구간이다.

벡터를 결합해 질문당 평균 **531.11토큰**을 더 넣었다(짝지은 차이의 95% 구간 514.51~547.41, n=150). 로컬 제공자는 가상 사용자별 기억을 다섯 번의 배치로 임베딩했고, 질문 150건에 각각 새 임베딩을 계산했다. 로컬 HTTP 호출과 모델 추론 시간을 후보 p95에 포함했다.

키워드를 단독 실행한 기준선에서도 질문 150개 모두 같은 순서의 기억을 선택했고 추정 토큰 수가 일치했다. 이 실행의 p95는 4.73ms였다(95% 구간 4.36~5.48). 무관 질문에서 키워드가 잘못 검색한 한 건은 “강변 순회 정비에 다음 달에도 참가하려면 어디에 신청서를 내야 해?”였다. 짐받침 나사와 페달 수리 기록 두 건이 선택됐지만, 신청 장소에 관한 정보는 없었다. [키워드 단독 실행의 질문별 결과](independent_quality.json)

키워드 기준은 0.30이고, DB는 프로세스 안의 SQLite다. 신뢰구간은 고정한 다섯 상황에서 질문을 표집할 때의 불확실성을 나타낸다. 제공자는 시험 조직에 등록한 로컬 ORT 가중치를 사용했다. 실제 조직 자료, 네트워크 DB, Nori 분석기, 다른 한국어 임베딩 모델을 사용하면 별도 측정이 필요하다.
