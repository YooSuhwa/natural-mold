# 기억 회상 평가 사전 등록 (PR-B2)

작성일: 2026-11-07. 보고용 분할을 돌리기 전에 고정한다(기획 `memory-policy-plan.md` 7장, 5.4, 5.5).
바꾸면 아래 "변경 기록"에 날짜와 이유를 남긴다.

## 데이터

- 합성 데이터(실존 인물·개인정보 없음). 가상의 10명 × 기억 30개 = 300개, 질문 160개
  (사람마다 같은 단어 3, 조사 붙은 질의 3, 바꿔 말하기 3, 시간 2, 여러 턴 참조 2, 관련 없음 3).
- 기억 작성 `gpt-5.4-mini`, 질문 작성 `claude-sonnet-5`(기억 작성자와 다른 모델), 모두 사내 LiteLLM 게이트웨이.
- 같은 정답 기억을 공유하는 질문은 한 묶음이다. 묶음 단위로 조정용(`tune`)·보고용(`report`) 분할에
  나눈다(시드 15, 범주 개수 균형). 관련 없음 질문은 각자 한 묶음이다.
- 사람마다 DB를 비우고 그 사람의 기억만 `memory_writes.write_memory`로 넣는다(후보 = 그 사람의 기억).

## 평가 대상

실제 `memory_recall.rank` → `select_within_budget`(범위 상한 4/4, 1,500토큰). **실제로 넣는 목록**으로 잰다.
키워드는 접미사 목록(`korean_terms` 대비책, OpenSearch 없음).

## 비교군

| 이름 | 내용 |
|---|---|
| `keyword` | 임베딩 없음(키워드만 설치) |
| `vector` | `text-embedding-3-large@1024`만(키워드 기준을 도달 불가로) |
| `rrf` | 키워드 + `text-embedding-3-large@1024`, RRF(k=60). 현재 코드 그대로 |
| `rrf_cos` | `rrf`의 검색 점수를 `0.7·RRF + 0.3·코사인`으로 바꿔 다시 정렬(GBrain) |
| `rrf_small` | 키워드 + `text-embedding-3-small@1024`(비교 열, 기준은 따로 조정) |

## 기준값 조정 (조정용 분할만)

1. `KEYWORD_FLOOR`: `keyword`에서 0.15~0.70(0.05 간격). 관련 없음 "넣지 않음" ≥ 0.9인 값 중
   같은 단어 + 바꿔 말하기 recall@10 합이 가장 큰 값. 같으면 큰 값(보수적).
2. 코사인 기준: 1에서 정한 `KEYWORD_FLOOR`를 고정하고 `rrf`(large), `rrf_small`(small) 각각에서
   0.20~0.70(0.02 간격), 같은 목적 함수. 키워드 기준을 하나로 두는 것은 두 설치 형태가 같은 상수를 쓰기 때문이다.
3. 가중치 `WEIGHTS`는 바꾸지 않는다(이번 범위 밖, 민감도는 보고하지 않음).

## 지표 (범주별, 보고용 분할)

- recall@10, nDCG@10(이진 관련도): 넣은 목록 기준.
- 관련 없음: "넣지 않음" 비율. `false_fire_rate` = 관련 없음 턴에 하나라도 넣은 비율.
- 넣은 기억 중 정답 비율(쓸모 있는 비율, 관련 있는 질문만), 평균 넣은 토큰.
- 95% 신뢰구간: 묶음 단위 부트스트랩 2,000회(시드 15), 비교군 간 차이는 같은 표본으로 짝지어 계산.
- 회상 지연: 질문마다 `rank` + `select_within_budget` 시간(질의 벡터는 캐시에서, 네트워크 제외).
  질의 임베딩 한 번의 게이트웨이 지연은 따로 잰다.

## 통과 기준

| 설치 형태 | 비교군 | 기준 |
|---|---|---|
| 임베딩 있음 | `rrf` | 같은 단어 recall@10 ≥ 0.85, 바꿔 말하기 recall@10 ≥ 0.7, 관련 없음 "넣지 않음" ≥ 0.9 |
| 키워드만 | `keyword` | 같은 단어 recall@10 ≥ 0.85, "넣지 않음" ≥ 0.9. 바꿔 말하기는 보고만 |

판정: 점추정이 기준 이상이면 **통과**. 신뢰구간 상한이 기준 − 0.02보다 낮으면(구간 전체가 −2점 아래)
**실패**. 그 사이는 **경계**(통과 아님, 기능은 켜지 않는다). 기준을 못 넘은 구성은 끈 채로 낸다.
`rrf_cos`는 `rrf`보다 같은 단어·바꿔 말하기 recall@10의 짝지은 차이 구간이 0을 넘을 때만 채택을 권한다.

## 변경 기록

- 2026-11-07: 조정 결과를 본 뒤 사후(post hoc) 민감도 구성(`posthoc_*`: 키워드 0.3/0.35, large 코사인
  0.42/0.44)을 보고용 분할에 더 돌렸다. 판정·기준·목적 함수는 바꾸지 않았고, 사후 구성은 판정에 쓰지 않는다.
  이유: 키워드 목적 함수가 0.35~0.5에서 동점이라(같은 단어 1.0, 바꿔 말하기 0) 동점 규칙이 0.5를 골랐고,
  large 0.40은 조정용 분할에서도 "넣지 않음" 경계(0.93)였다.
