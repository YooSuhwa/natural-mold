# 워크플로 AI 편집 평가 (W5a, 반복 L-d, 나머지 노드, 2026-11-09)

재실행: `cd backend && .venv/bin/python -m evals.workflow_edit.run`
(모든 응답이 `cache/llm.json`에 있어 재실행은 게이트웨이 호출 0회이고 결과는 결정적이다. 원자료와 제안된 정의는 `results.json`.)
모델: 사내 LiteLLM 게이트웨이 `gpt-5.4-mini`, `claude-sonnet-5`. 경로: API와 같은 `ai_edit.propose`(편집 명령 적용 → 정의 검증 →
게시 검사, 고쳐 보내기 최대 2회 — 나머지 노드로 도구 스키마가 커져 2회로 늘렸다). 에이전트는 가짜 5개(문의 분류, 답변 작성, 주간 보고, 웹 조사, 품질 검사).

## 사례

| 사례 | 시작 | 요청 요지 | 통과 조건 |
|---|---|---|---|
| `q3_from_scratch` | 빈 초안 | 분류 → 긴급이면 승인 → 답변 초안, 거절은 실패 | 제안, 게시 검사 0건, 노드 종류(시작·에이전트·판단·승인·출력·실패), 분류·답변 에이전트 |
| `weekly_report` | 빈 초안 | 주간 보고 → 위험이 있으면 승인 후, 없으면 바로 내보내기 | 같은 기준, 주간 보고 에이전트 |
| `research_summary` | 빈 초안 | 웹 조사 → 요약 작성 → 제목·본문 두 필드 출력 | 조사가 요약으로 이어짐, 출력 필드 2개 |
| `edit_timeout` | Q3 템플릿 | 승인 기한을 2시간으로, 나머지 그대로 | 바뀐 노드가 `review` 하나, `timeout_minutes` 120, 연결 그대로 |
| `rewrite_loop` | 빈 초안 | 작성 → 검사, 떨어지면 의견을 반영해 다시(최대 3번), 넘으면 내 승인 | 반복 1개, `max_rounds` 3, 한도 초과 갈래가 승인, 다시 쓰는 단계가 앞 회차 검사 의견을 읽음(`previous`) |
| `ambiguous` | 빈 초안 | "문서 처리하는 흐름 하나 만들어 줘" | 되묻기(`question`) |
| `fanout_research` | 빈 초안 | 하위 주제 목록 → 하위 주제마다 조사 → 모델로 한 번에 요약 | 노드 종류에 `for_each`·`llm`, 웹 조사 에이전트만 |
| `switch_triage` | Q3 템플릿 | category가 refund면 승인, bug면 바로 답변, 그 밖은 실패(긴급 판단 제거) | `switch`의 경우 값에 refund·bug |
| `ask_then_notify` | 빈 초안 | 강조할 점을 묻고(하루 넘으면 실패) 반영해 주간 보고 → 앱 알림 → 내보내기 | `ask`·`notify`·`fail`, 주간 보고 에이전트만 |
| `llm_judge` | 빈 초안 | 답변이 정중한지 모델이 판단해 정중하면 내보내기, 아니면 실패 | `decision_bool`의 `evaluator` `llm` |

## 결과

| 모델 | 통과 | 고쳐 보내기 | 입력·출력 토큰(합) |
|---|---|---|---|
| `gpt-5.4-mini` | 9/10 | 2건(`llm_judge` 2회 뒤 통과, `ambiguous` 2회 뒤에도 되묻지 않고 흐름을 만듦 → 실패) | 142,898 / 9,464 |
| `claude-sonnet-5` | 10/10 | 1건(`research_summary`) | 145,928 / 9,687 |

- 나머지 노드 4건을 두 모델 모두 게시 검사 0건으로 만들었다(`ambiguous`만 gpt 실패). 항목마다는 목록 값을 `source`·`path`로
  짚고 항목을 `item` 참조로 넣었고, 여러 갈래는 경우 이름과 `default`를 모두 이었다.
- **gpt-5.4-mini는 실행마다 흔들린다.** 프롬프트를 고치며 돌린 다섯 번에서 매번 다른 사례 하나가 떨어졌다(`q3_from_scratch`,
  `switch_triage`, `llm_judge`, `ambiguous`). 같은 요청이라도 표본이 바뀌면 결과가 달라지는 수준이므로, 시스템 모델을
  고를 때는 Claude 쪽이 안정적이다(화면에서는 실패하면 "다시 요청"과 확인할 것 목록으로 드러난다).

### 나머지 노드에서 고친 것 (평가로 찾음)

1. **설명만 하고 명령이 아무것도 바꾸지 않았다**(gpt, `edit_timeout`). 결과가 초안과 같으면 고쳐 보내기로 되돌린다
   (`ai_edit.NO_CHANGE`).
2. **새 노드를 더하기 전에 연결했다**(gpt). 노드 명령을 먼저, 연결 명령을 그다음에 적용한다(각각 순서 유지). 없는 노드를
   지우거나 없는 연결을 끊는 명령은 결과가 같으므로 받아들인다.
3. **추가하지 않은 노드에 연결했다**(gpt). 고쳐 보내기에 "연결한 노드는 같은 답에서 add_node로" 안내와 명령 뒤의 노드 ID
   목록을 붙인다.
4. **필드 이름을 한글로 반복했다**(gpt). 이름 규칙 위반이면 "영문 snake_case, 한글은 label" 안내를 붙이고, 규칙 문구에도 넣었다.
5. **요청에 없는 분류·검사 에이전트를 더했다**(gpt). "요청한 에이전트 단계만" 규칙을 넣었다.
6. **입력을 선언하지 않고 참조했다**(gpt). "참조하는 입력은 같은 답에서 set_inputs로" 규칙을 넣었다.

### L-d에서 고친 것 (평가로 찾음)

1. **gpt가 다시 쓰는 단계에 검사 의견을 넘기지 않았다**(반복은 맞지만 같은 글만 되풀이하는 흐름). 시스템 프롬프트에 "검사에 떨어져
   다시 하는 단계는 그 의견을 `previous` 참조로 받아야 한다"와 반복 예시 하나를 넣었다.
2. **gpt가 출력 형식에 `minItems`를 썼고**, 고쳐 보내도 반복했다. 허용 키(type, properties, required, items, enum,
   description)를 프롬프트에 적었다.
3. **gpt가 새 노드를 `update_node`로 만들려 했다.** 명령 설명을 "`add_node`는 초안에 없는 ID, `update_node`는 있는 ID"로
   바꾸고, 고쳐 보내기 메시지에 "새 노드는 `add_node`로"를 붙였다.
4. **Claude가 올바른 인자를 `{"$PARAMETER_NAME": {...}}`로 한 번 더 감싸 보냈다**(게이트웨이를 거친 Claude 도구 호출의 버릇).
   서버가 알 수 없는 키 하나로 감싼 인자를 한 겹 벗긴다(`ai_edit.unwrapped`, 단위 시험).

## 한계

- 사례 6개 × 모델 2개로 작다. 승인 대상 범위가 넓어지는 W5b 화면 시험과 실제 사용 기록으로 넓힌다.
- 에이전트 이름·설명이 요청과 잘 맞는 경우만 봤다. 맞는 에이전트가 없을 때 되묻는지는 시스템 프롬프트 규칙으로만 둔다.
