몰디 채팅을 AG-UI 1.0으로 바꿀 수 있을까?

브라우저에 보내는 채팅 이벤트는 표준화할 수 있다. 실행을 한 번만 수행하고, 권한을 확인하고, 끊긴 대화를 이어 보는 일은 몰디 서버가 계속 책임져야 한다.

판단

브라우저용 신규 채팅 계약에는 AG-UI 1.0 도입을 권한다. assistant-ui의 공식 AG-UI 런타임을 사용할 수 있고, Python Deep Agents도 LangGraph 어댑터를 통해 같은 형식의 이벤트를 보낼 수 있다. 몰디에서는 기존 워커가 실행을 한 번 수행하고, 같은 저장 기록에서 현재 형식과 AG-UI 출력을 각각 만드는 방식을 권한다.

현재 대화는 이미 assistant-ui와 LangGraph SDK를 사용한다. 그 위에 몰디가 명령 접수, 조직 권한, 이벤트 저장, 체크포인트 분기, 재접속을 얹었다. 공식 FastAPI 예제처럼 새 요청이 바로 그래프를 실행하게 바꾸면 이 경로들을 다시 연결해야 한다.

특히 승인 후 재개와 끊긴 화면의 복구가 다르다. AG-UI의 승인 응답은 같은 스레드의 새 실행을 시작한다. 반면 HTTP+SSE 표준에는 끊긴 구독을 같은 실행에 다시 붙이는 기능이 없다. 이미 메일을 보냈을 수 있는 작업에서 새로고침이 새 실행을 만들면 안 된다.

의존성 실험. 몰디의 pyproject.toml과 uv.lock 복사본에 Python 프로토콜 1.0.0과 어댑터 0.0.48을 추가하고 uv lock --no-sources를 실행했다. 현재 Deep Agents를 고정하면 패키지 3개만 추가됐다. 0.7.42 후보에서는 langchain-google-genai 4.5.3이 선택되어 google-genai가 2.34.0에서 3.6.1로 바뀌었고 LangSmith·모델 제공자 패키지도 함께 바뀌었다. Google 어댑터 4.5.3은 google-genai 3.3.0 이상을, Deep Agents가 허용하는 어댑터 하한 4.4.3은 2.20.0 이상을 요구한다. 의존성 해석과 실제 모델 회귀 검증은 별도다.

권고 순서. 현재 기준인 Deep Agents 0.7.32와 LangGraph 1.2.19에서 확보한 결과를 바탕으로, 업그레이드 후보인 Deep Agents 0.7.42와 LangGraph 1.2.24를 같은 채팅 통신으로 검증한다. 후보 조합은 LangChain 1.5.2, Core 1.8.5 이상을 요구한다. 잠금 파일의 변경 목록을 확인하고 기존 체크포인트·승인·서브에이전트·첨부·재접속, 실제 공급자의 도구 호출·사용량까지 통과한 뒤 AG-UI 개발을 시작한다.

몰디 선언은 deepagents==0.7.42와 langgraph>=1.2.24,<2를 제안한다. AG-UI 개발 단계에 ag-ui-protocol>=1.0.0,<2를 추가하고 공식 FastAPI 브리지 비교 환경에 ag-ui-langgraph[fastapi]==0.0.48을 둔다. 범위 선언은 허용 버전을 뜻하고, 실제 검증 버전은 uv.lock으로 고정한다. 기존 화면의 프런트엔드 잠금은 이 백엔드 검증을 마친 뒤 따로 변경한다.

STEP 이벤트는 기본 메시지 파트로 보이지 않고, RAW와 알 수 없는 이벤트도 기본 UI에 표시되지 않는다. CUSTOM은 별도 데이터 파트로 보이지만 다음 요청의 메시지에 자동 포함되지 않는다. 영속 카드와 감사 기록은 몰디 원장에서 복원해야 한다.

Deep Agents · LangGraph

create_deep_agent의 결과는 컴파일된 LangGraph다. 공식 문서는 Agent Server + TypeScript 어댑터 경로를 소개하고, 로컬 FastAPI에서 Python LangGraphAgent로 직접 감싸는 통합도 제공한다.

Python 어댑터는 기본 LangGraph 이벤트 수집 버전이 v2이고, 몰디의 기본 수집은 v3이다. 예제 엔드포인트는 요청마다 그래프를 구동한다. 기존 워커를 구독하려는 몰디에서는 권한·수명·중복 방지를 고려한 연결이 필요하다.

1. 기준 기록과 적합성 시험현재 저널에 일반 답변·여러 모델 메시지·도구·승인·자식·분기·취소와 과거 이벤트를 준비한다.같은 기록을 두 표현으로 재생한다. 공식 스키마, 순서 검사, 최종 메시지 상태, 권한별 공개 필드를 각각 검사한다. 비교 중 실제 실행과 외부 도구 호출은 각각 한 번만 일어난다.

3. 새 출력 투영기1단계 기록과 2단계 검증을 통과한 런타임. 루트·자식·메시지·도구 호출 ID 대응표와 종료 사유 계약.정상 시작과 조기 RUN_ERROR, 정상 종료와 뒤늦은 RUN_ERROR를 각각 검사한다. RUN_FINISHED 시점에 열린 자식이 없어야 한다. 자식 출력·복수 메시지·도구 결과·토큰이 제자리에 놓인다. 멀티테넌트 비식별 시험에서 권한 밖 정보 노출 0건.
