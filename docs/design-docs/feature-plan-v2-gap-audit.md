## 2. 항목별 빈칸

표의 "처리 시점"은 다음 셋 중 하나다. **지금**: 작고 독립적이라 11번 전에 끝낸다. **11·13과 함께**: 가드레일·승인 작업이 있어야 의미가 있다. **결정 필요**: 사용자가 정할 일이다.

|---|---|---|---|

| 1-2 | 기획서 0A의 "기능 현황판 정정"(기준 소스 갱신)은 하지 않았다. 현황판은 78dbb5f 기준이다 | 기획서 현황판 표시 기준 | 결정 필요 (기획서를 갱신할지) |

### 3번 Deep Agents 목표 patch (14.4절 1단계)

PoC(#333)는 0단계 범위와 같다. 제품 적용(#339)은 기획서 C3 1단계와 다음이 다르다.

의도된 차이(사용자 결정, 2026-11-05): Kubernetes + gVisor + `secure_access` 대신 docker 런타임, 대화 단위 대신 호출 단위. 기획서 15.3절도 docker 모드는 "개발과 소규모 시험에만" 쓴다고 했으므로, 다중 회사 운영 전에는 2단계(Kubernetes) 전환이 필요하다.

### 6번 일반 첨부의 모델 전달 (11.2절, 11.7절 "첨부 모델 전달")

맞는 것: 실행 접수 시 첨부 고정과 실행 시작 시점 모델 기준 판정, 호출마다 재확인, vision 미지원 모델에 이미지 미전달, 실행 기록(`attachment_inputs`), 텍스트·이미지·PDF 전달. PDF 텍스트 추출은 기획서(B3 2단계)보다 앞서 했다.

| # | 빈칸 | 기획서 요구 | 현재 | 처리 시점 |
|---|---|---|---|---|
| 6-1 | 전송 전 미리보기 | 입력창 파일 칩에서 어떻게 전달될지 미리 보여 줌(예: "설명문으로 전달" 배지) | 전송 뒤 메시지 버블에만 "모델에 전달 안 됨" 표시(#337) | 지금 |
| 6-2 | 비전 미지원 모델의 대체 방식 | 설명문 변환(vision_describer, 설명 모델이 있으면 기본), 모델 전환 제안, 전송 차단(설명 모델이 없으면 기본) | 안내 문구만 넣고 이미지는 보내지 않음 | 지금 (vision_describer 역할은 B1 시스템 역할 추가가 필요) |
| 6-3 | 입력 능력 판정 순서 | 관리자 지정 → 제공사 모델 API → 카탈로그 → 시험 호출 | `models.supports_vision` 하나만 봄(null은 미지원) | 지금 (관리자 지정은 이미 같은 열. 카탈로그·시험 호출 추가) |
| 6-4 | 이미지 변환 시점과 기준 | 업로드 시 긴 변 2000px, 5MB 이하 JPEG/WebP 변환본을 만들어 모든 제공사에 같은 파일 | 모델 호출 때 3.75MB 초과 등만 긴 변 1568px로 줄임 | 지금 |
| 6-5 | 파생본 | 설명문·추출 텍스트를 원본 버전에 묶은 파생본으로 저장하고 재사용, 원본 삭제·권한 회수 시 함께 삭제 | 호출마다 다시 추출 | 지금 |
| 6-6 | 요약 시 오래된 이미지 | 대화 요약 때 오래된 이미지를 설명문으로 바꿈 | 최근 8장만 보내고 이전 이미지는 안내 문구로 바꿈 | 6-2 뒤 |

완료 증거 중 "모델이 실제로 받은 입력을 확인"은 실행 기록으로 확인할 수 있지만, 실제 제공사(live) 호출로는 확인하지 않았다(ADR-024 Consequences의 기록 규칙).

## 3. 처리 순서 제안

1. **지금 (11번 전):** 3-1·3-2·3-3, 4-2·4-3·4-4·4-5, 1-1. 작고 기획서와 바로 맞출 수 있다.
2. **지금, 묶어서 하나의 작업:** 6-1·6-3·6-4 (첨부 사전 판정과 변환), 이어서 6-5·6-2·6-6 (파생본과 설명문 변환).
3. **11·13과 함께:** 4-1·4-6.
4. **결정 필요:** 1-2 (기획서 현황판 갱신 여부), 4-7 (샌드박스 수명 단위).

이후 기능 PR은 ADR-024의 실행 계약 9항목 절과 기획서 해당 장의 완료 증거 대조 표를 함께 싣는다.
