# 가드레일·승인·감사·권한 최소 범위 계획 (기획서 v2 순번 11번)

> 기준: 기능 확장 기획서 v2(2026-10-27) 16장(C4 가드레일), 17장(C5), 27장(F2), 28장(F3), 31.2절(출시 단위 1B), 31.3절.
> 근거 자료: [korean-pii-detector-benchmark.md](korean-pii-detector-benchmark.md)(한국어 탐지기 측정), LangChain 공식 가드레일 문서, "Guardrails in LangChain" 글(Nayan Kunwar, Medium) 요약.
> 상태: 진행 중. 6절 2번(탐지 묶음 모듈) 구현: `backend/app/guardrails/detectors.py`.

## 1. 왜 지금, 무엇까지

순번 11번은 연결 기능(A1 문서 검색, A2 DB 연결, A3 OpenAPI 도구화)이 첫 출시 전에 통과해야 하는 통제 지점이다. 기획서는 "회사 강제 정책의 최소 버전 생성, 게시, 실행 고정을 포함하고, 중앙 운영 화면 완성까지 기다리지는 않는다"고 정했다. 그래서 이 계획은 **P0(11번 완료 조건)** 과 **P1(같은 C4 1단계지만 11번 뒤에 해도 되는 것)** 을 나눈다. 판정 모델(Kanana, Jev, LLM 판정)은 2단계(순번 26번)다.

## 2. 한국어 개인정보 묶음 (측정 결과 반영)

K-PII-Bench 3,000건 측정(엄격 span)에서 **ko-pii 플러그인 + Presidio 주민등록번호 인식기(C 구성)** 가 F1 0.57로 가장 좋았다. Presidio 공통 인식기는 한국어 조사가 붙은 값을 놓친다(이메일 재현율 0.23).

| 묶음 | 인식기 | 비고 |
|---|---|---|
| 공통 (`common`) | 비밀값(기존 `marketplace/secret_scan` 패턴, `re.ASCII`로 컴파일), ko-pii의 이메일·카드(Luhn)·IP | 언어 무관 |
| 한국 (`kr`) | ko-pii의 나머지 라벨(주민번호, 전화, 계좌, 주소, 이름 등), 검증 숫자로 거르지 않는 주민등록번호 정규식(Presidio `KrRrnRecognizer`와 같은 패턴) | 2020-10 이후 주민번호 뒷자리는 임의다. 측정 표본의 주민번호 1,257개 중 428개는 이 정규식만 찾는다 |
| 다른 나라 | Presidio 나라 묶음(`supported_countries`) | 첫 다른 나라 묶음을 넣을 때 Presidio를 의존성에 추가한다. 예: 폴란드는 `PlPeselRecognizer`(PESEL)만 있고, 이름·주소는 spaCy `pl` 모델 NER이 필요하다(미측정) |

- **구현에서 Presidio를 쓰지 않은 이유:** Presidio의 카드·IP 인식기는 `\b`로 끝나서 한국어 조사가 붙은 값(`4111…로`)을 놓친다. C 구성에서 Presidio가 맡은 것은 주민번호 정규식 하나였고, 그것만 옮겼다. Presidio를 넣으면 spaCy 등 의존성 20여 개가 따라온다. 모듈의 측정 결과는 C 구성과 같다(F1 엄격 0.571, 겹침 0.631, 문서당 p50 1.9 ms; `poc/korean-pii-bench/bench_packs.py`).

- 이름·주소는 규칙으로 F1 0.29다. `schift-ko-pii` 0.6.0(v7 모델) 기본 설정 + Presidio 주민등록번호 인식기는 전체 F1 0.78(이름 0.73, 계좌 0.81)이고 문서당 약 22 ms다(벤치마크 3.1절). 이것을 한국 묶음 기본으로 하고, 모델을 받을 수 없는 설치는 규칙 묶음(C 구성)으로 대체한다. 모델은 `trust_remote_code`로 저장소 코드를 실행하므로 고정 리비전(9d9bc145)과 코드 검토 뒤에만 쓰고, 가중치는 이미지에 넣거나 내부 저장소에서 받는다.
- `schift-ko-pii` 0.6.0은 `ko-pii==1.15.2`를 고정한다. 같은 Python 환경에 ko-pii 최신판(1.22.x)을 따로 넣을 수 없으므로 한 묶음 안에서는 schift가 가져오는 ko-pii만 쓴다.
- 실행 위치: 모델은 별도 컨테이너에서 돈다(2.1절). torch 스레드 1개 고정, 이미 검사한 메시지는 해시로 건너뛰고 새 내용만 검사, 이벤트 루프 밖 고정 크기 풀에서 실행하고 동시 실행 수를 제한한다. GPU가 있으면 선택적으로 쓴다(긴 입력에서 약 5배).
- 망 분리: ko-pii는 의존성과 네트워크 접근이 없다. (Presidio URL·이메일 검사는 처음 쓸 때 public suffix 목록을 인터넷에서 받으려 하므로, 나중에 Presidio를 넣으면 내장본만 쓰도록 고정한다.)
- 비밀값 패턴은 스트리밍 경로에서 돈다. URL 사용자정보 패턴이 `a.b.a.b…` 같은 긴 입력에서 제곱 시간(100 KB에 3.1초)이라, 스킴 길이를 32자로 제한했다(`secret_scan.py`, 업로드 검사에도 적용). 시험이 100 KB 입력 시간을 잡는다.
- 묶음마다 한국어 시험 세트(막아야 할 문장과 비슷하지만 통과해야 할 문장)를 둔다. 회귀 시험은 `poc/korean-pii-bench` 측정 방식을 CI용 소형 세트로 옮긴다.

### 2.1 모델 묶음 서비스 (`pii-detector`)

| 항목 | 내용 |
|---|---|
| 왜 별도 컨테이너인가 | torch(이미지 약 1.6 GB)와 모델 저장소 코드(`trust_remote_code`, transformers 전역 패치)를 백엔드 밖에 둔다 |
| 고정 | 리비전 `9d9bc145c573…`, 파일 6개 sha256(`docker/pii-detector/model_files.py`). 모델 코드는 검토한 v6 파일과 같은 바이트다. 해시가 다른 파일은 읽지 않는다 |
| 받기 | `pii-model-fetch`(1회)가 `pii_model` 볼륨에 받는다. 실패해도 0으로 끝나 스택 기동을 막지 않는다. 받을 수 없는 망은 `docker compose cp`로 넣는다 |
| API | `POST /detect {"texts": [...]}`(최대 64개, 1 MiB) → 텍스트별 `{entity, start, end, score}`. 라벨은 규칙 묶음과 같은 ko-pii 이름으로 바꿔 돌려준다. 본문은 로그에 남기지 않는다 |
| 접근 | 호스트 포트 없음, 비밀 값 없음. 스킬 샌드박스는 Compose 망에 닿지 않는다. 키(`PII_DETECTOR_API_KEY`)는 선택 |
| 대체 | URL이 없거나, 응답이 없거나, 잘못된 응답(개수 불일치, 범위 밖 span)이거나, 1 MiB를 넘는 텍스트는 `kr` 규칙 묶음으로 검사한다. 경고는 끊길 때와 돌아올 때 한 번씩 |
| 운영 설정 | 운영자 화면 `/settings/guardrail-model`(API `/api/guardrail-model-settings`): 켜기·끄기, 주소, 선택 키(시스템 `http_bearer` 자격증명), 연결 테스트, 기본값으로 되돌리기. 저장한 값(`guardrail_model_settings`, 플랫폼 행 하나)이 환경변수보다 우선하고, 지우면 환경변수로 돌아간다. 실행 중에는 30초 캐시로 읽고 저장하면 그 프로세스의 캐시를 바로 비운다(다른 워커는 30초 안에 반영). 주소는 내부 주소가 정상이라 사설망을 막지 않는 대신 운영자만 바꾸고 시험할 수 있고, 리다이렉트를 따르지 않으며, 연결 테스트는 결과(연결됨·연결 불가·시간 초과·키 거부·모델 없음·잘못된 응답)만 돌려주고 응답 본문은 돌려주지 않는다. 변경·되돌리기·연결 테스트는 감사 이벤트(`guardrail_model_setting.update`/`.reset`/`.test`, 변경 전후 값)로 남는다 |
| 측정 | 서비스를 거친 `common,kr_model`: 엄격 F1 0.784, 겹침 0.915(3.1절 v7 기본 + 주민번호 정규식과 같음). 처리 시간은 Apple Silicon Docker Desktop에서 문서당 p50 약 60 ms. 같은 모델이 macOS 호스트에서는 22 ms였으므로 linux aarch64 CPU 빌드의 차이다. 스레드를 2·4개로 늘리면 오히려 느려진다(109 ms) |

## 3. 구현 설계

### 3.1 LangChain 기능의 재사용과 한계

| LangChain 기능 | 쓰는 곳 | 한계와 대응 |
|---|---|---|
| `PIIMiddleware(detector=...)` | 처리 방식 이름과 의미를 맞춘다: `redact`, `mask`, `hash`, `block` | 인스턴스 하나에 종류 하나이고, `apply_to_input`·`apply_to_tool_results`는 `before_model`에서 **상태(대화 기록)를 직접 고친다**. ② LLM 송신 검사는 저장 기록을 바꾸지 않고 이번 호출만 바꿔야 하므로 Moldy 미들웨어의 `wrap_model_call`로 한다 |
| `PIIMiddleware` 스트림 변환기 (`apply_to_output=True`) | ⑤ 출력의 방출 전 가림 | `astream_events(version="v3")`, `run.messages`, `values`를 덮고 청크 경계에 걸친 값을 위해 앞부분을 붙잡아 둔다(lookback). Moldy 채팅도 v3 경로라 적용될 가능성이 높지만, SSE 투영·저장 이벤트(다시 보기)·추적까지 덮는지 **P0 첫 작업으로 시험**한다. 안 덮는 곳은 Moldy 투영 단계에 같은 검사를 붙인다 |
| `HumanInTheLoopMiddleware` | ③ "승인 요청" 조치 | 이미 쓰는 중(위험 도구 기본 승인). 가드레일 규칙이 승인 대상을 추가하는 경로만 더한다 |
| Langfuse 클라이언트 `mask` 함수 | 추적 | 스트림 변환기는 콜백을 덮지 않는다. 추적의 모델 출력(스트리밍 토큰, 최종 응답)은 콜백으로 수집되므로 Langfuse `mask`에 같은 탐지기를 연결한다 |
| `before_agent` / `after_agent` + `jump_to: "end"` | ① 입력 차단 | `after_agent`만으로는 이미 스트리밍된 내용을 막지 못한다(기획서 16.8절). ⑤는 위 스트림 변환기와 `after_model` 검사로 한다 |

### 3.2 미들웨어 배치

- 다섯 단계는 미들웨어 하나(`GuardrailMiddleware`)가 훅별로 맡는다: ① `before_agent`, ② `wrap_model_call`, ③④ `wrap_tool_call`(호출 전 인자, 호출 뒤 결과), ⑤ `after_model` + 스트림 변환기.
- **첨부보다 안쪽에 둔다.** `wrap_model_call`은 먼저 등록한 미들웨어가 바깥이다. ②가 첨부 본문(텍스트·PDF 추출본)까지 검사하려면 `AttachmentInputMiddleware`보다 뒤에 등록해 펼쳐진 요청을 보게 한다.
- 기존 장치(도구 위험도 승인, SSRF 차단, 파일 권한, 샌드박스)는 그대로 두고 가드레일보다 먼저 적용된다.
- **lease 경로**: 현재 내장 외 미들웨어가 붙은 구성을 거부한다. 회사 정책이 "기본 적용" 또는 "강제"이면 첨부와 같은 방식으로 기본 경로로 대체 실행하고 사유(`guardrail_policy`)를 남긴다. 두 경로를 각각 시험한다.

### 3.3 처리 방식

| 방식 | 동작 | 기본 쓰임 |
|---|---|---|
| 차단(block) | 요청 또는 응답을 멈추고 안내 문구. ③에서는 실행을 끝내지 않고 "정책 X로 차단됨, 같은 인자로 다시 시도하지 말 것"을 도구 오류로 돌려준다 | 비밀값 입력, 사외 모델로 가는 주민등록번호(②) |
| 치환(redact) | `[주민등록번호]` 같은 자리표시로 바꾼다 | ⑤ 출력, ④ 도구 결과 |
| 부분 마스킹(mask) | 일부만 남긴다(예: 끝 4자리) | 사용자가 식별해야 하는 경우 |
| 해시(hash) | 같은 값은 같은 토큰. **회사별 비밀키 HMAC**으로 만든다. 주민등록번호처럼 값 공간이 작은 항목은 일반 해시로 바꾸면 전수 대입으로 되돌릴 수 있다 | 같은 사람 여부를 추적해야 하는 경우 |
| 경고 | 기록만 한다 | 관찰 모드 |
| 승인 요청 | ③ 단계에서 기존 승인 카드로 보낸다 | 외부 전송 도구 인자에 개인정보 |
| 가명(pseudonymize) | 사외 모델로 갈 때만 대화별로 일정한 가명으로 바꾸고, 모델 답변과 (규칙이 허용하면) 도구 인자에서 원래 값으로 되돌린다. 3.3.1절 | 이름·주소처럼 모델이 문맥을 알아야 하는 항목 |

#### 3.3.1 가명 처리와 복원

참고: PIIGhost(MIT, LangChain `create_agent` 미들웨어), LLM Guard Anonymize/Deanonymize(2026-07 보관됨), `langchain_experimental` `PresidioReversibleAnonymizer`, LiteLLM `output_parse_pii`. 그대로 쓸 수 있는 것은 없고(유지 중단, 초기 단계, 한국어·스트리밍·Moldy 저장 경로 미지원) 아래 설계는 그 구조를 참고했다.

| 항목 | 설계 | 근거 |
|---|---|---|
| 가명 모양 | 기본은 표지형 `<<PERSON_1>>`(라벨은 영어 고정, 번호는 대화 안에서 일정). 규칙별로 자연형(`홍길동`, 형식 유지 번호)을 고를 수 있다 | 표지형은 스트림에서 여는 기호부터 최대 128자만 붙잡으면 복원된다(PIIGhost `PlaceholderStreamDecoder`). 자연형은 알려진 가명 목록 전체를 경계까지 붙잡아야 하고, 모델이 `홍 과장`처럼 바꿔 쓰면 놓친다 |
| 자연형 한국어 이름 | 원래 이름과 **받침 유무가 같은** 가명을 고르고, 성·이름 단독형도 대응표에 넣는다. 이번 대화에 나온 단어와 겹치는 가명은 쓰지 않는다 | `이상윤은` → `김하나은`처럼 조사가 틀어지는 것을 막는다 |
| 어디서 바꾸나 | ② `wrap_model_call`이 **이번 호출의 메시지 사본**만 바꾼다. 저장 기록·체크포인트·화면은 원래 값을 유지한다. 도구 결과(④)도 다음 모델 호출 때 같은 자리에서 바뀐다 | PIIGhost는 `before_model`에서 상태를 고쳐 체크포인트에 가명이 남는다. Moldy는 3.1절 원칙(저장 기록 불변)을 따른다 |
| 어디서 되돌리나 | (a) `wrap_model_call`이 돌려주는 AI 응답(상태·체크포인트에 원래 값으로 저장), (b) SSE 스트림 투영(붙잡기 버퍼), (c) 도구 인자는 규칙의 `restore_for_tools`가 참일 때만, `request.override`로 새 요청을 만들어 되돌린다(상태의 tool_call 사전은 고치지 않는다) | 스트리밍 토큰은 (a)보다 먼저 SSE로 나가므로 (b)가 따로 필요하다. 사외 검색 도구처럼 실제 값이 필요 없는 도구는 가명 그대로 받는다 |
| 추적 | Langfuse는 모델 호출 콜백을 받으므로 가명만 본다. 모델 출력 토큰도 가명 상태로 기록된다 | 3.1절 Langfuse `mask`와 같은 결과를 별도 처리 없이 얻는다 |
| 대응표 | 대화별 `guardrail_pseudonyms`(가명 → 원래 값, Cipher V2 암호화, 회사 범위 RLS). 대화 삭제·계정 삭제·보존 기간 정리 때 함께 지운다. 프로세스 캐시는 TTL로 제한한다 | 대응표가 곧 개인정보다(가명정보의 추가정보 분리 보관). PIIGhost는 다중 워커에서 메모리 캐시가 남는 문제를 TTL로 막는다 |
| 모델이 만든 가짜 표지 | 발급하지 않은 `<<PERSON_9>>`가 나오면 되돌리지 않고 남긴 뒤 탐지 기록에 남긴다 | PIIGhost 기본은 예외 발생. Moldy는 답변을 끊지 않고 기록한다 |
| 모델이 먼저 꺼낸 값 | 기본은 사용자·도구 내용에서 찾은 값만 가명 처리한다. 모델 답변에만 처음 나온 값(공인 이름 등)은 그대로 둔다(규칙으로 바꿀 수 있음) | PIIGhost의 provenance(`assistant_strategy=PRESERVE`)와 같다 |
| 완료 증거 | 가짜 모델로 (1) 청크 경계에 걸친 표지 복원, (2) 저장 기록·체크포인트에 원래 값, 사외 모델 요청과 Langfuse에 가명, (3) `restore_for_tools` 참·거짓 각각 도구가 받은 인자, (4) 자연형의 조사·성 단독형 복원율 | — |

### 3.3.2 규칙 묶음: 미들웨어가 받는 입력

미들웨어는 언어와 무관하다. 실행 때 확정된 **규칙 목록**만 받는다. 규칙 하나 = 탐지 묶음(`common`, `kr`, `kr_model`, 나중에 `us` 등) + 항목(`RRN`, `PERSON`, ... 또는 전체) + 단계(②③④⑤) + 처리 방식(3.3절)과 옵션(마스킹 자리수, 가명 모양, `restore_for_tools`).

- "한국어 전체", "한국어 주민번호·전화만", "미국 영어만"은 모두 규칙 목록으로 표현한다. 템플릿은 이 목록에 이름과 버전을 붙인 것이다(3.4절).
- 처리 방식은 규칙마다 정하므로 에이전트마다, 한 에이전트 안에서도 항목·단계마다 다르게 할 수 있다. 회사 정책이 잠근 규칙(예: 주민번호 차단)은 에이전트에서 바꿀 수 없다(3.4절).

  | 에이전트 예 | 템플릿 | 규칙 |
  |---|---|---|
  | 상담 요약 | 한국어 가명 | 이름·주소 → 가명, 전화·계좌 → 가명(형식 유지), 주민번호 → 차단 |
  | 사내 공지 작성 | 한국어 마스킹 | 이름 → `이**`, 전화 → 끝 4자리, 주민번호 → `[주민등록번호]` |
  | 해외 고객 응대 | 미국 영어(`us` 묶음 이후) | SSN → 차단, 이름 → 가명 |

- 3단계(미들웨어)는 코드에 둔 기본 템플릿 하나로 동작하고, 4단계에서 회사 정책·회사 템플릿·에이전트 적용이 같은 모양의 목록을 만든다. 미들웨어는 4단계에서 바뀌지 않는다.
- 미국 영어 묶음(`us`)은 Presidio 미국 인식기(SSN, 전화, 여권, 운전면허, ITIN, 은행 계좌)와 spaCy `en` NER로 만든다. 한국어처럼 영어 PII 데이터로 측정한 뒤 별도 PR로 넣는다(2절 "다른 나라").

### 3.4 정책, 버전, 실행 고정

- 회사 정책: `tenants.settings["guardrails"]` = `{mode, default_template, locked_rules}`. 모드는 `off`(회사 에이전트 전부 끔), `open`(템플릿을 고른 에이전트만), `default`(고르지 않은 에이전트는 기본 템플릿, 다른 템플릿·끄기 가능), `enforced`(모든 에이전트가 기본 템플릿). 잠근 규칙(`locked_rules`)은 에이전트가 다른 템플릿을 고르거나 끄거나 처리 방식을 바꿔도 남는다. 회사가 정책을 저장하지 않았으면 설치 기본값(`GUARDRAIL_DEFAULT_TEMPLATE`)이 `default`(잠금 없음)로, 비어 있으면 `open`으로 동작한다. API는 `/api/tenants/{id}/guardrails`(구성원 읽기, `can_manage_tenant` 변경, If-Match 버전). 위험 등급별 기본 조치는 5단계.
- 템플릿: 참조는 `builtin:<이름>`(코드) 또는 `company:<uuid>`. 회사 템플릿은 `guardrail_templates`(초안 규칙, draft/published/archived)와 `guardrail_template_versions`(게시할 때마다 버전+1, 게시본은 바뀌지 않음). 규칙은 저장할 때 한 번 검증한다(`app/guardrails/templates.py`). 회사 기본 템플릿은 보관할 수 없다. 게시 전 시험 세트 통과는 아직 넣지 않았다.
- 에이전트 적용: `agent_guardrail_bindings`(모드 `inherit`/`template`/`off`, 템플릿 참조, 규칙별 끄기·처리 방식 변경). API `/api/agents/{id}/guardrails`(`agent#can_edit`). `enforced`에서 `inherit` 외 모드, 잠근 규칙의 변경은 409. 응답에 다음 실행이 받을 규칙(`effective`)을 보여 준다. 해석은 `app/guardrails/policy.py`의 `resolve` 하나이며, 기본 템플릿을 쓸 수 없으면 검사 없이 실행하지 않고 실패한다.
- **실행 고정(ADR-024 §4)**: 채팅 실행은 접수 후 시작 전에 해석한 규칙 전체(꺼짐이면 `null`)를 `conversation_runs.metadata_json["guardrails"]`에 남기고(`app/guardrails/pinning.py`), 승인 응답으로 재개하는 실행은 같은 대화의 마지막 고정값을 그대로 쓴다. 트리거·Agent API·후속 질문 제안은 실행 시작 때 해석한다. 정책 변경은 다음 실행부터. 감사 `guardrail.policy_update`, `.template_create`/`_update`/`_publish`/`_archive`, `.binding_update`(전후 값).
- 판정 모델이 없으면 정규식·사전 규칙만 실행하고, 모델이 필요한 규칙은 "판정 모델 미설정"으로 표시한다.

### 3.4.1 미들웨어를 거치지 않는 경로 (3단계 첫 시험)

deepagents 0.7.32 코드 확인 결과, 아래 경로는 등록만으로는 덮이지 않는다. 3단계 PR에서 각각 시험으로 잠근다.

| 경로 | 문제 | 대응 |
|---|---|---|
| 요약(compaction) 미들웨어 | 긴 대화 요약을 자기 모델로 직접 호출한다. 가드레일이 요약보다 안쪽이면 요약 호출로 원문이 사외 모델에 간다 | 가드레일을 요약보다 바깥에 두거나 요약 호출에도 같은 검사를 붙이고, 요약 요청에 원래 값이 없는지 시험한다 |
| 하위 에이전트 | 메인 에이전트의 미들웨어는 포크된 하위 에이전트에만 물려준다. 선언형·범용 하위 에이전트는 따로 넣어야 한다 | `deep_agent_factory`가 모든 하위 에이전트 스택에 같은 가드레일(같은 규칙 목록)을 넣고, 하위 에이전트 모델 호출을 시험한다 |
| 에이전트 밖 모델 호출 | 빌더, 어시스턴트, 제목 생성 등은 에이전트 미들웨어를 타지 않는다 | 호출 지점을 목록으로 만들고 덮을지·제외할지(제외 사유)를 문서와 시험으로 정한다 |
| 스킬 스크립트의 외부 호출 | 미들웨어가 볼 수 없다 | 샌드박스 네트워크 정책(skill-sandbox-docker.md)이 맡는다 |
| 후속 질문 제안(입력창 고스트) | 대화 끝부분을 시스템 모델로 보낸다 | **덮음**: 같은 규칙으로 검사하고, 차단이면 제안을 만들지 않는다(`followup_service._guarded_transcript`) |
| 어시스턴트, 에이전트 빌더, 스킬 빌더, 이미지 생성, 스킬 평가, 모델 시험 | Moldy의 운영 프롬프트와 작성자 입력이 시스템 모델로 간다 | **제외**(현재): 에이전트 실행이 아니다. 회사 정책 적용 범위는 4단계에서 정한다. 새 모델 호출 지점은 `tests/test_guardrail_model_call_sites.py`가 검토 없이는 통과시키지 않는다 |
| 사외 모델 출구 전체 | 위 목록에 빠진 경로 | 2단계 게이트웨이(기획서 16장 CEL과 같은 판정 모듈)를 최후 방어선으로 둔다. 탐지 묶음은 그때 재사용한다 |

### 3.5 기록

- `guardrail_events`: 실행 ID, 단계, 템플릿·버전, 규칙, 검사 방식, 판정, 조치, 소요 ms, 시간 초과·오류. 원문은 해시만.
- 감사: 정책·템플릿·적용 변경(전후 값), 차단과 승인 전환. 마스킹·경고는 탐지 기록에만(27.5절).
- 추적: Langfuse 관찰 기록 `as_type="guardrail"`, 실행 지표에 단계별 가드레일 시간.

## 5. 완료 증거 (기획서 16장 기준 + 측정)

1. 차단형 규칙이 있을 때 검사 전 내용이 SSE, 저장 이벤트(다시 보기), 추적 어디에도 보이지 않는다.
2. 문장 경계·청크 경계로 나뉜 주민등록번호가 가려진다.
3. 회사 강제 정책을 게시하면 다음 실행부터 적용되고, 진행 중 실행과 승인 대기 요청은 이전 버전을 유지한다.
4. 판정 모델이 없을 때 정규식 규칙만 실행된다.
5. 사외 모델로 가는 요청에 주민등록번호가 있으면 정책대로 막히거나 가려지고, 저장된 대화 기록은 바뀌지 않는다(②).
6. 회사가 "승인 필요"로 정한 도구 호출은 에이전트 설정으로 끌 수 없다.
7. 기본 경로와 lease 경로를 각각 시험한다.
8. 한국 묶음이 측정 데이터 기준선(F1 0.57) 이상이고, 묶음을 바꾸면 같은 측정으로 비교한다.
9. 가명 규칙이 있을 때 사외 모델 요청과 추적에는 가명만, 화면·저장 기록에는 원래 값이 있고, 청크 경계에 걸친 가명도 복원된다(3.3.1절).
10. 요약 호출, 하위 에이전트 호출에 같은 규칙이 적용되고, 에이전트 밖 모델 호출은 덮거나 제외 사유가 문서에 있다(3.4.1절).

## 6. 작업 순서

1. **스파이크(1~2일)**: `PIIMiddleware` 스트림 변환기가 Moldy SSE·저장 이벤트·추적을 덮는지, `wrap_model_call` 변경이 저장 기록에 남지 않는지 시험.
   - 1차 결과(2026-11-05, 최소 에이전트 + 가짜 모델, langchain 1.4.7): `astream_events(version="v3")` 이벤트 17건 중 원래 값이 남은 이벤트 0건, 체크포인트의 AI 응답도 가려짐. 그러나 `apply_to_input`은 **사용자 메시지를 저장 기록에서도 바꾸고**, 콜백(`on_llm_new_token`, `on_llm_end`)에는 **원래 값이 남는다**. 그래서 ②는 `wrap_model_call`로, 추적은 Langfuse `mask`로 처리한다(3.1절). Moldy 실제 SSE 투영·저장 이벤트 확인은 구현 PR의 시험으로 한다.
2. 탐지 묶음 모듈(공통·한국 규칙)과 소형 회귀 세트. **구현됨**: `app/guardrails/detectors.py`, `tests/test_guardrail_detectors.py`. 모델 묶음(`kr_model`)도 **구현됨**: 별도 컨테이너 `pii-detector`(`docker/pii-detector`)와 백엔드 클라이언트 `app/guardrails/model_pack.py`(2.1절).
3. `GuardrailMiddleware`(②③④⑤) + 처리 방식 + 탐지 기록 + 스팬. 입력은 규칙 목록(3.3.2절), 첫 시험은 우회 경로(3.4.1절), 이어서 가명 처리(3.3.1절).
   - **3-1 구현됨**: `app/guardrails/{rules,actions,middleware,run}.py`. ②(이번 호출 사본만), ③(차단 시 도구 오류), ④(결과를 모델·저장 전에 처리), 처리 방식 차단·치환·마스킹·해시(회사별 HKDF 키)·경고, 기본 템플릿 `kr-default`·`kr-observe`(`GUARDRAIL_DEFAULT_TEMPLATE`, 기본 꺼짐, 모르는 이름이면 실행 실패), 요약 래퍼와 하위 에이전트 주입, 후속 질문 제안 검사, lease 대체(`guardrail_policy`). 시험 `tests/test_guardrail_middleware.py`(가짜 모델로 실제 에이전트 빌드). 래퍼를 빼면 요약 호출로 주민번호가 나가는 것을 시험으로 확인했다.
   - **3-2a 구현됨(⑤ 출력)**: 단계 `output` 추가(`kr-default` v2: 비밀값·식별번호 치환, 연락처 마스킹, 이름·주소 기록). `GuardrailStreamTransformer`(`app/guardrails/stream.py`)가 v3 프로토콜 이벤트를 내장 변환기보다 먼저 바꾼다. `messages`(텍스트·추론·도구 인자 델타), `tools`(도구 입력·출력), `values`(상태 스냅샷의 AI·도구 메시지). 스트림 텍스트는 128자 앞부분을 붙잡아 두고 128자마다 한 번 검사해 내보내며(탐지 호출 수 제한), 남은 끝부분은 `content-block-finish`의 검사된 전체 텍스트로 나간다(프론트 `@langchain/langgraph-sdk` 조립기가 그 블록으로 교체). 차단 규칙은 안내 문구로 바뀐다. 모델 응답은 그래프가 저장하기 전에 같은 규칙으로 한 번 더 검사한다. 예전 `stream_mode="messages"` 경로는 운영 경로가 아니라 저장 시 검사만 받는다. 시험 `tests/test_guardrail_output_stream.py`(3글자씩 스트리밍하는 모델, Moldy 프로토콜 수집 경로 포함).
   - **3-2b 구현됨(기록)**: `guardrail_events`(i11, 회사 RLS `DIRECT_TENANT`, 회사·대화와 함께 삭제). 검사 한 번·단계·규칙·항목·처리마다 한 행: 횟수, 템플릿·버전, 실행·대화·에이전트, 회사 키 HMAC 값 요약(최대 20개)만 남기고 원문·값은 남기지 않는다. 차단은 감사 `guardrail.block`(사유=규칙, 단계·항목·템플릿). 검사마다 Langfuse `as_type="guardrail"` 관찰(`guardrail.<stage>`, 결정 수, 차단 여부, 소요 ms). 기록은 훅마다 모아 한 번에 쓰고 실패해도 실행을 막지 않는다. 스레드가 대화 행이 아니면(API·트리거) 대화 칸을 비운다. 보존 기간: 회사 감사 기록 보존 기간(`audit_retention_days`)이 지나면 일일 `retention_sweep`이 함께 지운다(`retention.purge`에 `guardrail_events` 수, 기간을 줄일 때의 미리보기에도 포함).
   - **3-3 구현됨(가명, 표지형)**: 처리 방식 `pseudonymize`, 규칙 옵션 `restore_for_tools`. `kr-default` v3은 이름·주소를 사외 모델에 `<<PERSON_1>>`처럼 보내고(같은 대화 안에서 같은 사람은 같은 번호), 모델 답변(저장·스트림)과 `restore_for_tools`가 참인 도구 인자에서 원래 값으로 되돌린다. 대응표 `guardrail_pseudonyms`(i12, Cipher V2 암호화, 회사 키 HMAC 조회, 회사 RLS, 대화·회사와 함께 삭제, 실행마다 한 번 읽고 새 표지만 씀). 대화 행이 없는 스레드는 실행 동안만 유지. 발급하지 않은 표지는 그대로 두고 센다. 스트림 붙잡기(128자)는 표지 최대 길이(52자)보다 길다. 키 회전 시 이전 키가 목록에 있는 동안 복호화된다(자격 증명 회전 작업은 이 표를 다시 암호화하지 않는다).
   - **3-4 구현됨(자연형 가명, 사람 이름만)**: 규칙 옵션 `pseudonym_style="natural"`, 템플릿 `kr-natural`. 2·3음절 한글 이름은 같은 길이·같은 받침 유무의 지어낸 이름으로 바꾼다(조사 유지). 이번 텍스트·대응표의 이름과 이름(성 제외) 부분이 겹치는 후보는 건너뛴다. 그 밖의 이름·항목은 표지형으로 남는다. 형식 유지 가짜 번호는 넣지 않았다: 실제로 배정된 번호와 겹칠 수 있고, 복원이 빠지면 남의 번호가 답변에 남는다. 요약 래퍼와 본 미들웨어가 같은 요청을 두 번 검사하므로 이미 발급한 가명은 다시 가명 처리하지 않는다(시험으로 확인).
   - 복원 범위(결정적 시험, `tests/test_guardrail_natural_pseudonyms.py`): 전체 이름 + 조사(은/는/이/가/에게/의)·직함은 복원, 이름만 쓴 형태(`준호 씨`, `준호님`)는 단어로 설 때만 복원, 다른 단어 안의 이름 부분은 그대로, 성만 쓴 형태(`김 과장`)는 누구인지 알 수 없어 복원하지 않는다. 실제 LLM이 가명을 어떻게 바꿔 쓰는지(복원율)는 실제 모델로 측정해야 하며 아직 하지 않았다.
   - 이름만 쓴 형태의 경계는 조사·호칭·문장부호 목록(`pseudonyms._FOLLOWERS`)으로 판단한다. 나중 항목: 형태소 분석기(Kiwi `kiwipiepy`, LGPL v3)로 경계를 품사로 판단하고, 받침이 안 맞는 경우의 조사 교정과 규칙 묶음의 이름 후보(고유명사) 보강을 K-PII-Bench와 실제 LLM 답변 복원율로 비교한 뒤 도입을 정한다. Nori(Apache 2.0)는 Lucene(Java) 기반이라 Python 백엔드에서 직접 쓰기 어렵다.
4. 회사 정책·템플릿·버전 고정·감사 이벤트.
   - **4-1 구현됨(백엔드)**: 3.4절. i13(세 테이블, 회사 RLS `DIRECT_TENANT`). 시험 `tests/test_guardrail_policy.py`(모드·잠금·변경·API·고정과 재개), `tests/test_guardrail_policy_entry_points.py`(채팅·트리거·Agent API가 회사 정책을 받음). 다음: 4-2 회사 관리 화면(정책·템플릿 편집), 4-3 에이전트 가드레일 카드.
   - **4-2 구현됨(회사 관리 화면)**: 설정 → 회사 → 가드레일(`/settings/company/guardrails`). 구성원은 정책을 읽기만, 회사 관리자는 적용 방식·기본 템플릿·잠근 규칙을 저장하고, 회사 템플릿을 기본 제공·게시 템플릿에서 복사해 만들고 규칙별 처리 방식·검사 단계·가명 옵션을 고친 뒤 게시·보관한다. 규칙이 무엇을 찾는지(묶음·항목)는 복사한 그대로 둔다. 시험 `tests/components/guardrails`, E2E `e2e/guardrail-company-settings.spec.ts`. 이 작업에서 CORS 허용 헤더에 `If-Match`가 빠져 프론트와 백엔드 출처가 다를 때(기본 3000→8001) 버전을 보내는 회사·조직 쓰기가 브라우저에서 모두 막히던 것을 고쳤다.
   - **4-3 구현됨(에이전트 카드)**: 에이전트 설정 → 설정 탭의 가드레일 카드. 회사 정책 설명, 적용(회사 따름/템플릿 선택/끔), 템플릿 선택, 규칙별 켜기·끄기와 처리 방식(회사 잠금 규칙은 바꿀 수 없음), 끌 때 남는 잠금 규칙 수, 저장된 설정으로 다음 실행이 받는 템플릿·규칙 수. 회사가 끄면 안내만, 강제면 회사 따름만 고를 수 있다. API 응답에 회사 기본 템플릿 참조(`policy_default_template`)를 더했다(끈 규칙을 다시 켤 수 있게 목록을 보여 주기 위해). 시험 `tests/components/guardrails/agent-guardrail-card.test.tsx`, E2E는 `e2e/guardrail-company-settings.spec.ts`의 에이전트 시나리오.
5. 위험 등급별 기본 조치(C5 최소)와 lease 경로 대체 실행.
   - **5-1 구현됨(백엔드)**: `tenants.settings["guardrails"]["tool_risk"]` = 위험 등급(`read_only`, `write_internal`, `external_mutation`, `code_execution`, `unknown`)별 `allow`/`approval`/`block`. 저장하지 않은 등급은 지금 동작(조회 허용, 나머지 승인 필요). `app/guardrails/tool_risk.py`가 루트와 선언형 하위 에이전트마다 적용한다: 차단 등급 도구는 도구 목록에서 빼고 `ToolRiskMiddleware`가 모델 요청에서 숨기고 호출을 거부한다(Deep Agents 자체 도구 `write_file`/`edit_file`=내부 쓰기, `execute`=코드 실행 포함). 승인 필요는 승인 항목을 넣고(에이전트 설정으로 끌 수 없음), 허용은 기본 승인만 뺀다(에이전트가 직접 건 승인은 남김). 탐지 모드와 무관하게 적용되고, 표준 에이전트만 대상이다. 규칙과 함께 실행에 고정(`metadata_json["guardrails"]["tool_risk"]`)되어 재개는 고정값을 쓴다. 트리거·Agent API도 시작 때 해석한다. 트리거는 기존 규칙(트리거 안전하지 않은 도구가 있으면 실행 중단)을 유지하되 회사가 차단한 도구는 실행되지 않으므로 세지 않는다. 정책 PUT에서 `tool_risk`를 빼면 저장된 값을 유지한다(4-2 화면 호환). 시험 `tests/test_guardrail_tool_risk.py`. 5-2: 회사 화면 칸, 에이전트 카드 표시.
   - **5-2 구현됨(화면)**: 회사 가드레일 화면의 "도구 위험 등급별 기본 조치" 카드(등급별 허용·승인 필요·차단, 기본값 표시, 트리거 안내, 구성원은 읽기만; 저장 시 모드·템플릿은 현재 값 그대로 보냄). 에이전트 카드 아래에 회사가 정한 등급별 조치를 읽기 전용으로 표시(회사가 탐지를 꺼도 보임). 시험 `tests/components/guardrails`, E2E `e2e/guardrail-company-settings.spec.ts` 도구 위험 시나리오.
   - 미룸: ③ 단계 규칙의 "승인 요청" 조치(검사 중 승인 카드와 재개 흐름이 새로 필요), lease 경로 지원(`PREPARED_RUN_LEASE_ENABLED` 기본 꺼짐, 첨부와 함께).
6. P1(① 입력, 가드레일 카드 화면, 기존 미들웨어 이전).
