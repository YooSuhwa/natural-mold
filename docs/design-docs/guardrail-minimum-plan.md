# 가드레일·승인·감사·권한 최소 범위 계획 (기획서 v2 순번 11번)

> 기준: 기능 확장 기획서 v2(2026-10-27) 16장(C4 가드레일), 17장(C5), 27장(F2), 28장(F3), 31.2절(출시 단위 1B), 31.3절.
> 근거 자료: [korean-pii-detector-benchmark.md](korean-pii-detector-benchmark.md)(한국어 탐지기 측정), LangChain 공식 가드레일 문서, "Guardrails in LangChain" 글(Nayan Kunwar, Medium) 요약.
> 상태: 계획. 코드 변경 없음.

## 1. 왜 지금, 무엇까지

순번 11번은 연결 기능(A1 문서 검색, A2 DB 연결, A3 OpenAPI 도구화)이 첫 출시 전에 통과해야 하는 통제 지점이다. 기획서는 "회사 강제 정책의 최소 버전 생성, 게시, 실행 고정을 포함하고, 중앙 운영 화면 완성까지 기다리지는 않는다"고 정했다. 그래서 이 계획은 **P0(11번 완료 조건)** 과 **P1(같은 C4 1단계지만 11번 뒤에 해도 되는 것)** 을 나눈다. 판정 모델(Kanana, Jev, LLM 판정)은 2단계(순번 26번)다.

| 영역 | P0 (11번 완료 조건) | P1 (이어서) | 범위 밖 |
|---|---|---|---|
| C4 가드레일 | 5단계 훅 중 ②③④⑤, 한국·공통 개인정보 묶음, 비밀값 규칙, 회사 정책 4방식과 규칙 잠금, 정책·템플릿 최소 버전(생성·게시·실행 고정·취소), 관찰 모드, 탐지 기록, GUARDRAIL 스팬, 차단형 출력 규칙의 방출 전 검사 | ① 입력의 탈옥 패턴 목록, 에이전트 가드레일 카드 화면, 기존 PII·모더레이션 미들웨어 이전, 기본 템플릿 5종 | 판정 모델, 조직 정책, 버전 비교 화면, CEL 인자 조건(2단계, 게이트웨이와 함께) |

## 2. 한국어 개인정보 묶음 (측정 결과 반영)

K-PII-Bench 3,000건 측정(엄격 span)에서 **ko-pii 플러그인 + Presidio 주민등록번호 인식기(C 구성)** 가 F1 0.57로 가장 좋았다. Presidio 공통 인식기는 한국어 조사가 붙은 값을 놓친다(이메일 재현율 0.23).

| 묶음 | 인식기 | 비고 |
|---|---|---|
| 공통 | 비밀값(기존 `marketplace/secret_scan` 패턴 재사용), 카드(Luhn), IP | 언어 무관. Presidio 공통 이메일·URL은 한국어 문장에서 쓰지 않음 |
| 한국 | ko-pii Presidio 플러그인(33개 라벨 중 매핑된 것), Presidio `KrRrnRecognizer` | 주민등록번호는 2020-10 이후 뒷자리가 임의라 검증 숫자로 거르지 않는 Presidio 인식기를 함께 둔다 |
| 다른 나라 | Presidio 나라 묶음(`supported_countries`) | 예: 폴란드는 `PlPeselRecognizer`(PESEL)만 있고, 이름·주소는 spaCy `pl` 모델 NER이 필요하다(미측정) |

- 이름·주소는 규칙으로 F1 0.29다. `schift-ko-pii-v6`(34M)를 더하면 이름 0.71, 주소 0.40, 전체 0.77이 된다(벤치마크 3.1절). CPU 지연이 문서당 약 0.6초라 P0에서는 선택형 "모델 묶음"으로 두고, 기본은 규칙 묶음이다. GPU·ONNX·양자화로 지연을 줄이는 것과 v7 비교는 P1. 모델은 `trust_remote_code`로 저장소 코드를 실행하므로 고정 리비전과 코드 검토 뒤에만 쓴다.
- Presidio URL·이메일 검사는 처음 쓸 때 public suffix 목록을 인터넷에서 받으려 한다. 망 분리 설치를 위해 내장본만 쓰도록 고정한다.
- 묶음마다 한국어 시험 세트(막아야 할 문장과 비슷하지만 통과해야 할 문장)를 둔다. 회귀 시험은 `poc/korean-pii-bench` 측정 방식을 CI용 소형 세트로 옮긴다.

## 3. 구현 설계

### 3.1 LangChain 기능의 재사용과 한계

| LangChain 기능 | 쓰는 곳 | 한계와 대응 |
|---|---|---|
| `PIIMiddleware(detector=...)` | 처리 방식 이름과 의미를 맞춘다: `redact`, `mask`, `hash`, `block` | 인스턴스 하나에 종류 하나이고, `apply_to_input`·`apply_to_tool_results`는 `before_model`에서 **상태(대화 기록)를 직접 고친다**. ② LLM 송신 검사는 저장 기록을 바꾸지 않고 이번 호출만 바꿔야 하므로 Moldy 미들웨어의 `wrap_model_call`로 한다 |
| `PIIMiddleware` 스트림 변환기 (`apply_to_output=True`) | ⑤ 출력의 방출 전 가림 | `astream_events(version="v3")`, `run.messages`, `values`를 덮고 청크 경계에 걸친 값을 위해 앞부분을 붙잡아 둔다(lookback). Moldy 채팅도 v3 경로라 적용될 가능성이 높지만, SSE 투영·저장 이벤트(다시 보기)·추적까지 덮는지 **P0 첫 작업으로 시험**한다. 안 덮는 곳은 Moldy 투영 단계에 같은 검사를 붙인다 |
| `HumanInTheLoopMiddleware` | ③ "승인 요청" 조치 | 이미 쓰는 중(위험 도구 기본 승인). 가드레일 규칙이 승인 대상을 추가하는 경로만 더한다 |
| `before_agent` / `after_agent` + `jump_to: "end"` | ① 입력 차단 | `after_agent`만으로는 이미 스트리밍된 내용을 막지 못한다(기획서 16.8절). ⑤는 위 스트림 변환기와 `after_model` 검사로 한다 |

### 3.2 미들웨어 배치

- 다섯 단계는 미들웨어 하나(`GuardrailMiddleware`)가 훅별로 맡는다: ① `before_agent`, ② `wrap_model_call`, ③④ `wrap_tool_call`(호출 전 인자, 호출 뒤 결과), ⑤ `after_model` + 스트림 변환기.
- **첨부보다 안쪽에 둔다.** `wrap_model_call`은 먼저 등록한 미들웨어가 바깥이다. ②가 첨부 본문(텍스트·PDF 추출본)까지 검사하려면 `AttachmentInputMiddleware`보다 뒤에 등록해 펼쳐진 요청을 보게 한다.
- 기존 장치(도구 위험도 승인, SSRF 차단, 파일 권한, 샌드박스)는 그대로 두고 가드레일보다 먼저 적용된다.
- **lease 경로**: 현재 내장 외 미들웨어가 붙은 구성을 거부한다. 회사 정책이 "기본 적용" 또는 "강제"이면 첨부와 같은 방식으로 기본 경로로 대체 실행하고 사유(`guardrail_policy`)를 남긴다. 두 경로를 각각 시험한다.

### 3.3 처리 방식

| 방식 | 동작 | 기본 쓰임 |
|---|---|---|
| 차단(block) | 요청 또는 응답을 멈추고 안내 문구. ③에서는 실행을 끝내지 않고 "정책 X로 차단됨, 같은 인자로 다시 시도하지 말 것"을 도구 오류로 돌려준다 | 비밀값 입력, 사외 모델로 가는 주민등록번호(②) |
| 치환(redact) | `[주민등록번호]` 같은 자리표시로 바꾼다 | ⑤ 출력, ④ 도구 결과 |
| 부분 마스킹(mask) | 일부만 남긴다(예: 끝 4자리) | 사용자가 식별해야 하는 경우 |
| 해시(hash) | 같은 값은 같은 토큰. **회사별 비밀키 HMAC**으로 만든다. 주민등록번호처럼 값 공간이 작은 항목은 일반 해시로 바꾸면 전수 대입으로 되돌릴 수 있다 | 같은 사람 여부를 추적해야 하는 경우 |
| 경고 | 기록만 한다 | 관찰 모드 |
| 승인 요청 | ③ 단계에서 기존 승인 카드로 보낸다 | 외부 전송 도구 인자에 개인정보 |

### 3.4 정책, 버전, 실행 고정

- 회사 정책: `tenant.settings`의 가드레일 항목(모드 off/open/default/enforced, 기본 템플릿, 규칙별 allow_off/locked/hidden, 위험 등급별 기본 조치). 기존 회사 정책 API(`/api/tenants/{id}/policies`, If-Match 버전)를 넓힌다.
- 템플릿: 기본 제공 템플릿은 코드에 두고, 회사 템플릿은 `guardrail_templates`(draft/published, version) 테이블. 게시는 시험 세트 통과 후.
- 에이전트 적용: `agent_guardrail_bindings`(none/all/per_stage, 템플릿 버전, 끈 규칙).
- **실행 고정(ADR-024 §4)**: 실행 접수 때 적용될 회사 정책 버전과 템플릿 버전을 실행 기록(`conversation_runs.metadata_json["guardrails"]`)에 남기고, 진행 중 실행·승인 대기·재개는 그 버전을 쓴다. 정책 변경은 다음 실행부터.
- 판정 모델이 없으면 정규식·사전 규칙만 실행하고, 모델이 필요한 규칙은 "판정 모델 미설정"으로 표시한다.

### 3.5 기록

- `guardrail_events`: 실행 ID, 단계, 템플릿·버전, 규칙, 검사 방식, 판정, 조치, 소요 ms, 시간 초과·오류. 원문은 해시만.
- 감사: 정책·템플릿·적용 변경(전후 값), 차단과 승인 전환. 마스킹·경고는 탐지 기록에만(27.5절).
- 추적: Langfuse 관찰 기록 `as_type="guardrail"`, 실행 지표에 단계별 가드레일 시간.

## 4. 참고 글에서 반영한 것

| 글의 주장 | 기획서와 비교 | 반영 |
|---|---|---|
| 결정론적 + 모델 기반 혼합, 미들웨어로 단계마다 배치 | 같음(16.8절 순서) | 그대로 |
| PII 처리 4방식 redact·mask·hash·block | 기획서 조치 목록에 해시가 없음 | 3.3절에 추가. 해시는 회사별 HMAC |
| 입력에 `password`·`api_key` 같은 민감 단어가 있으면 차단 | 기획서는 ⑤ 출력의 비밀값 마스킹 위주 | ① 입력과 ② 송신에 비밀값 규칙 추가(기존 비밀값 패턴 재사용) |
| HITL은 checkpointer와 thread_id가 있어야 동작 | 이미 충족(AsyncPostgresSaver) | 해당 없음 |
| `after_agent`에서 작은 모델로 독성 판정 후 대체 문구 | 기획서는 출력 방출 전 검사를 요구(16.8절) | `after_agent`만으로는 이미 흘러간 스트림을 못 막는다는 점을 3.1절에 명시 |
| 비즈니스 규칙(예: 일정 금액 이상 환불은 승인)을 가드레일로 강제, "규칙 집행을 LLM에 맡기지 말라" | 기획서 16.2절 CEL 인자 조건, 게이트웨이와 같은 판정 모듈(2단계) | P0는 위험 등급별 기본 조치까지. 인자 조건은 2단계 유지 |
| `before_agent`에서 인증·속도 제한 | Moldy는 인증·사용 한도를 라우터와 실행 접수에서 이미 처리 | 가드레일에 넣지 않음 |

## 5. 완료 증거 (기획서 16장 기준 + 측정)

1. 차단형 규칙이 있을 때 검사 전 내용이 SSE, 저장 이벤트(다시 보기), 추적 어디에도 보이지 않는다.
2. 문장 경계·청크 경계로 나뉜 주민등록번호가 가려진다.
3. 회사 강제 정책을 게시하면 다음 실행부터 적용되고, 진행 중 실행과 승인 대기 요청은 이전 버전을 유지한다.
4. 판정 모델이 없을 때 정규식 규칙만 실행된다.
5. 사외 모델로 가는 요청에 주민등록번호가 있으면 정책대로 막히거나 가려지고, 저장된 대화 기록은 바뀌지 않는다(②).
6. 회사가 "승인 필요"로 정한 도구 호출은 에이전트 설정으로 끌 수 없다.
7. 기본 경로와 lease 경로를 각각 시험한다.
8. 한국 묶음이 측정 데이터 기준선(F1 0.57) 이상이고, 묶음을 바꾸면 같은 측정으로 비교한다.

## 6. 작업 순서

1. **스파이크(1~2일)**: `PIIMiddleware` 스트림 변환기가 Moldy SSE·저장 이벤트·추적을 덮는지, `wrap_model_call` 변경이 저장 기록에 남지 않는지 시험.
2. 탐지 묶음 모듈(공통·한국, Presidio + ko-pii, 망 분리 설정)과 소형 회귀 세트.
3. `GuardrailMiddleware`(②③④⑤) + 처리 방식 + 탐지 기록 + 스팬.
4. 회사 정책·템플릿·버전 고정·감사 이벤트.
5. 위험 등급별 기본 조치(C5 최소)와 lease 경로 대체 실행.
6. P1(① 입력, 가드레일 카드 화면, 기존 미들웨어 이전).
