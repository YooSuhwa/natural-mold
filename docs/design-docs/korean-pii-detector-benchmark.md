# 한국어 개인정보 탐지기 비교 — Presidio 한국 인식기 vs ko-pii (2026-11-05)

> 목적: 가드레일(기획서 v2 16장, 순번 11번)의 한국 개인정보 묶음을 고르기 전에 후보를 같은 데이터로 잰다.
> 코드: `poc/korean-pii-bench/bench.py`. 원본 데이터와 문서별 결과는 저장소에 넣지 않는다. 계획: [guardrail-minimum-plan.md](guardrail-minimum-plan.md).

## 1. 결론

**한국 묶음은 `schift-ko-pii` 0.6.0(v7 모델, 기본 설정) + Presidio 주민등록번호 인식기로 한다.** 엄격 F1 0.78, 겹침 F1 0.92이고 문서당 약 22 ms(CPU 스레드 1개)다. 모델 없이 쓰는 규칙 묶음 기준선은 ko-pii Presidio 플러그인 + Presidio 주민등록번호 인식기(C 구성, F1 0.57)다. Presidio 공통 인식기(이메일·전화·카드·IP·URL)는 한국어 문장에서 조사가 붙으면 놓치거나 오탐이 많아 쓰지 않는다. 규칙만으로는 이름·주소가 F1 0.29에 그친다.

### 3.1 모델 기반 후보: schift-ko-pii v6·v7

## 4. 해석

- **조사가 붙은 값.** 정답 이메일의 76%는 바로 뒤에 한글 조사가 붙는다(`...@x.com으로`). Presidio 공통 인식기는 이 경우를 놓쳐 이메일·IP 재현율이 0.23이다. ko-pii는 1.00이다.
- **Presidio의 한국 고유 항목 부재.** 계좌, 건강보험, 차량번호, 주소, 이름은 Presidio에 한국어 인식기가 없다.
- **주민등록번호.** 정답 주민등록번호의 89%가 검증 숫자가 맞지 않는다(합성 데이터). ko-pii는 검증 숫자로 걸러 66%만 찾고, Presidio는 모두 찾는다. 2020년 10월 이후 발급 번호는 뒷자리가 임의 번호라 검증 숫자로 거르면 실제 번호도 놓칠 수 있으므로, Presidio 주민등록번호 인식기를 함께 둔다.
- **카드번호는 판단 보류.** 정답 카드번호의 91%가 Luhn 검증에 실패하는 값이다. 실제 카드번호는 Luhn을 통과하므로 낮은 재현율(0.12)은 데이터 특성이다.
- **URL.** Presidio URL 인식기는 이메일 도메인 등을 URL로 잡아 정밀도가 0.04다. ko-pii도 0.14로 낮아 정답 정의(span 경계) 차이를 따로 봐야 한다.
- **이름·주소.** 둘 다 F1 0.29. 기획서의 분류 모델(Kanana Safeguard Siren 등)이나 한국어 NER 모델이 필요한 영역이다.
- **망 분리.** Presidio의 URL·이메일 검사는 처음 쓸 때 public suffix 목록을 인터넷에서 받으려 한다(이 측정에서는 차단되어 내장본을 썼다). 망 분리 설치에서는 내장본을 쓰도록 설정해야 한다.

## 5. 한계

- 합성 데이터 한 종류이고 같은 작성자의 템플릿이다. 실제 업무 문서 성능을 보장하지 않는다.
- ko-pii 작성자가 같은 벤치마크로 평가한 적이 있어(규칙은 맞추지 않았다고 밝힘) ko-pii에 유리할 수 있다. 그 500건은 표본에서 뺐다.
- 채점은 이 문서의 매처 기준이며 K-PII-Bench 공식 BIO 점수가 아니다.
- 탐지만 쟀다. 마스킹 출력에 원문이 남는지는 따로 잰다.

## 6. 재현

```bash
python -m venv .venv && .venv/bin/pip install presidio-analyzer "ko-pii[presidio]" spacy
.venv/bin/python poc/korean-pii-bench/bench.py <test_track_a.jsonl> report.json 3000

# schift-ko-pii-v6 (별도 venv, 모델 폴더는 Hugging Face 리비전 f3c18072를 받아 둔 곳)
python -m venv .venv-schift && .venv-schift/bin/pip install "schift-ko-pii==0.4.0"
HF_HUB_OFFLINE=1 HF_HOME=./hfhome .venv-schift/bin/python poc/korean-pii-bench/bench_schift.py \
  <test_track_a.jsonl> <schift-ko-pii-v6 폴더> report_schift.json 3000

# v7: 패키지 0.6.0, 모델 폴더는 리비전 9d9bc145. 마지막 인자 default | off
python -m venv .venv-schift7 && .venv-schift7/bin/pip install "schift-ko-pii==0.6.0"
OMP_NUM_THREADS=1 HF_HUB_OFFLINE=1 HF_HOME=./hfhome .venv-schift7/bin/python poc/korean-pii-bench/bench_schift.py \
  <test_track_a.jsonl> <schift-ko-pii-v7 폴더> report_v7.json 3000 default
```

정확도는 위 명령의 결과이고, 처리 시간 표는 torch 스레드 1개로 300건을 따로 잰 값이다.
