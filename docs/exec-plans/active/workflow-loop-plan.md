# 워크플로 반복(되돌아가기) 기획

- 상태: **확정**, 2026-11-09. 결정 질문 L1~L7(4장)은 추천안으로 확정했다. 사용자가 방향을 정했다: "판단 노드에서 되돌아가는 선 +
  최대 횟수 필수 + 넘었을 때 할 일 필수", 추천대로 진행.
- 범위: 판단 노드의 한 갈래가 앞 단계로 되돌아가 같은 단계들을 다시 실행하는 **조건 반복** 하나. 목록의 항목마다 도는 반복(Iteration·Map),
  병렬, 반복 안의 반복은 이 문서 범위 밖이다.
- 근거: `workflow-plan.md`(1차 핵심, ADR-026), 다른 제품 조사(부록 A, 2026-11-09), 현재 코드(2장, `main` 1482538d).

## 1. 목표와 완료 기준

예: "초안 작성 → 품질 검사 → 통과?" 에서 통과하지 못하면 초안 작성으로 돌아가 검사 의견을 반영해 다시 쓰고, 세 번까지 해도 안 되면
담당자 승인으로 넘긴다.

완료 기준:

1. 판단의 되돌아가는 갈래를 타면 그 사이 단계들이 다시 실행되고, 다른 갈래를 타면 다음으로 진행한다. 회차마다 단계 기록이 따로 남고
   이전 회차 결과를 덮어쓰지 않는다.
2. 최대 횟수에 닿으면 반드시 "한도 초과" 갈래로 간다(실패 종료, 승인, 다른 단계 중 설계에서 고른 곳). 사유가 단계 기록과 감사에 남는다.
3. 무한 반복이 설계될 수 없다: 최대 횟수나 한도 초과 갈래가 없는 반복, 판단이 아닌 곳에서 되돌아가는 선, 겹치거나 안에 든 반복,
   반복 안의 승인·출력·실패 노드는 게시 검사가 막는다.
4. 반복 중 worker가 바뀌어도 같은 회차의 같은 지점부터 이어 가고, 단계가 두 번 실행되지 않는다(ADR-026 5절 그대로).
5. 다시 실행되는 에이전트가 앞 회차의 결과(예: 검사 의견)를 받아 볼 수 있다. 첫 회차에는 빈 값이다.
6. 화면: 캔버스에 되돌아가는 선과 "최대 N회"가 보이고, 실행 상세에 회차가 보인다.
7. 사용 한도에 닿으면 다음 회차를 시작하지 않고 한도 초과 갈래로 간다.

## 2. 현재 코드 (조사 결과)

- 게시 검사는 순환을 전부 막는다(`checks.py` `_has_cycle` → `cycle`). 참조 검사는 "시작에서 오는 모든 경로에서 앞에 있는 노드만"
  (지배 노드, `_dominators`)이다.
- 실행 기록은 노드당 한 줄이다: `workflow_step_runs`에 유일 제약 `uq_workflow_step_runs_node(run_id, node_id)`, 순서는 `position`.
  다음 노드는 마지막 단계와 그 갈래로 정한다(`runner._successor`). 앞 단계 값은 완료된 단계의 출력을 노드 ID로 모은다(`runner._values`,
  같은 노드가 여러 번이면 마지막 것이 남는 구조).
- 갈래 이름(`EdgeWhen`)은 `true/false/approved/rejected` 넷이다. 편집기 배치는 위→아래 자동 정렬(dagre)이고 끌어서 잇기는 없다.
  연결 바꾸기(PR #399)는 순환이 생기는 노드를 후보에서 뺀다.
- 결과 불명 확인 요청의 interrupt ID는 단계 ID 기준이라 회차가 늘어도 겹치지 않는다(`approvals.request_unknown_check`).

## 3. 설계

### 3.1 정의 스키마

판단 노드에 반복 설정을 두고, 한도 초과를 **세 번째 갈래** `limit`으로 표현한다. 한도 초과 뒤 할 일(실패·승인·다른 단계)은 따로 만들지 않고
그 갈래가 가리키는 노드로 정한다. 기존 연결 모델, 다음 단계 고르기, 버전 diff, AI 편집 명령을 그대로 쓴다.

```json
{"id": "passed", "type": "decision_bool", "label": "통과?",
 "condition": {"all": [{"source": "review", "path": "/passed", "op": "eq", "value": true}]},
 "repeat": {"max_rounds": 3}}

{"from": "passed", "to": "publish", "when": "true"},
{"from": "passed", "to": "draft",   "when": "false"},   // 되돌아가는 선
{"from": "passed", "to": "escalate","when": "limit"}    // 3회 해도 안 되면
```

- `repeat.max_rounds`: 1~10, 편집기 기본 3(L2). "회차" = 반복 구간이 실행되는 횟수(첫 실행 포함).
- 되돌아가는 선이 있는 판단은 `repeat`과 `limit` 갈래가 필수, 없는 판단은 둘 다 없어야 한다.
- **앞 회차 값 참조:** 참조 조각에 `"previous": true`를 더할 수 있다. 같은 반복 구간 안에서 "이 노드보다 뒤에 오는" 노드를 가리킬 때만
  허용되고, 그 노드의 직전 회차 출력으로 바뀐다(첫 회차는 빈 텍스트). 예: 초안 작성 프롬프트 `[{"text":"검사 의견: "},
  {"ref":{"node":"review","path":"/feedback","previous":true}}]`.

### 3.2 게시 검사

1. **되돌아가는 선의 정의:** 그 선을 빼고 본 그래프에서 도착 노드가 출발 노드를 지배하면(시작에서 출발 노드로 가는 모든 경로가 도착 노드를
   지나면) 되돌아가는 선이다. 출발은 판단 노드의 `true` 또는 `false` 갈래만(`loop_from_not_decision`).
2. 되돌아가는 선을 모두 뺀 그래프는 순환이 없어야 한다(기존 `cycle` 규칙). 즉 이 형태가 아닌 순환은 여전히 막는다.
3. **반복 구간** = 도착 노드에서 출발 판단까지의 경로에 있는 노드들. 판단 하나에 되돌아가는 선 하나, 구간끼리 겹치거나 안에 들 수 없다
   (`loop_overlap`). 구간 안에 승인·출력·실패 노드는 둘 수 없다(`loop_body_kind`, L4). 구간에서 밖으로 나가는 갈래는 판단의 나머지
   갈래와 `limit`뿐이다(`loop_exit`).
4. 되돌아가는 선이 있는 판단에 `repeat`이 없거나(`loop_limit_missing`) `limit` 갈래가 없으면(`loop_limit_exit_missing`) 막는다.
   `limit` 갈래는 구간 밖 앞쪽 노드로만 간다.
5. 참조: 기존 지배 노드 규칙은 되돌아가는 선을 뺀 그래프로 계산한다. `previous` 참조는 같은 구간에서 뒤에 오는 노드만(`ref_previous_scope`).
6. 구간 바깥에서 구간 안 노드를 참조하면 마지막 회차 값이다(설명 문구로 표시).

### 3.3 실행

- `workflow_step_runs`에 `round`(1부터, 기본 1) 열을 더하고 유일 제약을 `(run_id, node_id, round)`로 바꾼다(마이그레이션 i30). 단계 기록은
  계속 한 줄씩 쌓이고 `position`으로 정렬한다.
- 다음 노드 고르기(`_successor`): 판단 단계의 갈래가 되돌아가는 선이면, 그 판단이 이번 실행에서 완료된 횟수(회차)가 `max_rounds`보다 작고
  사용 한도가 남아 있으면 도착 노드로 간다. 아니면 갈래를 `limit`으로 바꿔 기록하고(`output.limit_reached`, `output.reason` =
  `max_rounds` 또는 `usage_limit`) `limit` 쪽으로 간다.
- 새로 만드는 단계의 `round` = 같은 노드의 기존 단계 수 + 1. 앞 단계 값은 노드마다 **가장 최근에 완료된** 출력이고(지금과 같음),
  `previous` 참조도 같은 값을 읽는다. 구간 안에서 뒤에 오는 노드는 이번 회차에 아직 실행되지 않았으므로 직전 회차 값이 된다. 없으면 빈 텍스트다.
- 회차 시작 전 사용 한도 확인(`UsageLimits.blocking`, 실행자 기준): 넘었으면 다음 회차를 시작하지 않고 `limit`으로 간다(완료 기준 7).
- 복구·결과 불명·취소·긴급 중지는 단계 행 기준이라 그대로다. 결과 불명 재실행은 같은 회차의 같은 행을 다시 쓴다(새 회차가 아니다).
- 따로 시간 한도는 두지 않는다(ADR-026 6절과 같은 이유). 반복은 횟수(≤10)와 노드 수(≤50)로 묶여 한 실행의 단계는 최대 500개다.
- 감사: `workflow.loop_limit`(대상 실행, 메타데이터 `decision_node_id`, `rounds`, `reason`)을 남긴다. 회차마다 남기지는 않는다(단계 기록에 있음).

### 3.4 화면

| 영역 | 설계 |
|---|---|
| 캔버스 | 되돌아가는 선은 배치 계산에서 빼고, 판단 노드 옆으로 돌아 도착 노드 왼쪽으로 들어가는 점선으로 그린다. 선 위에 "↺ 최대 3회" 배지. 반복 중인 판단은 핸들이 셋(예·아니오·한도 초과) |
| 노드 설정 | 판단 노드의 "다음 단계"에서 예/아니오 후보에 "↺ 되돌아가기" 묶음으로 앞 단계(지배 노드)를 보여 준다. 고르면 "반복" 칸이 열린다: 최대 횟수(1~10, 기본 3), "한도를 넘으면" 다음 단계(실패 종료·승인·다른 단계, 없으면 실패 종료 노드를 만들어 잇기 버튼). 판단이 아닌 노드의 후보에는 계속 순환 노드가 나오지 않는다 |
| 값 넣기 | 구간 안에서 뒤에 오는 노드의 값은 "앞 회차" 배지와 함께 고를 수 있다(`previous` 참조) |
| 검사 | 3.2 규칙을 화면에서도 돌려 "확인할 것"에 모은다 |
| 실행 상세 | 단계 목록에 "초안 작성 · 2회차"처럼 회차를 붙이고, 판단 요약에 "아니오 → 다시 (2/3)", 한도 초과면 "한도 초과 → 담당자 승인" |
| 버전 비교 | 되돌아가는 선과 `limit` 갈래도 같은 색 diff로 그린다 |
| AI 편집 | 시스템 프롬프트와 명령에 `repeat`, `limit`, `previous`를 더한다. 평가에 "검사에서 떨어지면 다시 쓰게, 최대 3번, 넘으면 내 승인" 사례를 더한다 |
| 템플릿 | "작성 → 검사 → 통과할 때까지 다시" 업무 템플릿 |
