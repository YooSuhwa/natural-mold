제품 기획

몰디의 기존 대화 워커는 브라우저가 끊겨도 일을 계속한다. 이번 개발에서는 한 번의 응답으로 일이 끝나지 않았을 때, 남은 목표와 최신 지시를 어떻게 이어갈지 정한다. 사용자는 같은 대화에서 결과와 근거를 확인한다. 실행 중 지시와 대화 복귀를 연결하는 방식은 일반 채팅의 AG-UI 1.0 전환에 정리했다.

목표와 실행의 수명을 분리한다

다음은 몰디에 추가할 설계다. 목표는 여러 실행의 결과를 묶고, 개별 실행은 기존 대화 워커와 체크포인트를 사용한다. 새 작업이 들어올 때마다 실행 권한과 비용을 다시 확인한다.

상태를 바꾸는 주체와 조건

목표 상태 제안전이 조건다음 행동
진행 중소유자가 활성 목표를 만들거나 중지 사유를 해소하고 재개한다.대화별 활성 실행 하나를 유지한다. 새 지시를 받을 때마다 기존 완료 판정을 무효화하고, 반영할 사용자 입력을 자동 후속 실행보다 먼저 처리한다.
승인 대기도구가 기존 승인 절차를 요청한다.자동 실행을 멈춘다. 승인 재개 때 주체·권한·인자·만료를 다시 확인한다.
일시정지 / 차단사용자가 멈추거나, 비용·횟수 한도, 무진전, 권한 회수, 외부 동작의 결과 불명이 발생한다.정지 사유와 마지막으로 확인한 동작을 남긴다. 재개 결정이 기록되기 전까지 새 작업을 예약하지 않는다.
완료 / 취소현재 버전의 모든 완료 조건에 유효한 근거가 있고 미반영 입력이 없거나, 사용자가 취소한다.종료 결정과 알림 발행 요청을 함께 저장한다. 중복 종료 이벤트는 같은 결과로 수렴한다.

후속 실행과 알림상태 전이와 다음 실행·알림 발행 의도를 같은 DB 트랜잭션에 기록한다. 소비자는 전이별 고유 키로 재시도하며 대상 기록과 처리 완료를 함께 확정한다.사용자 입력이 들어오면 목표 버전과 지시 순번을 재확인한다. 자동 후속은 새로운 실행으로 비용·권한 심사를 거친다. 승인 재개와 구별한다.

초기 구현에서 다룰 실행 경로

내부 검증에서 허용할 자동 실행  후속 실행은 허용된 조회와 버전을 남기는 몰디 내부 산출물 작성까지 수행한다. 메일 발송·외부 게시 등은 도구를 호출하기 전에 사용자에게 돌려준다. 작업 결과가 불명확하면 후속 예약도 멈춘다. 일반 외부 쓰기의 자동 실행 여부는 F06의 결과 기록과 복구 시험을 마친 뒤 검토한다.


일반 채팅부터 구현

목표 생성과 Steer는 사용자가 소유한 일반 채팅에서 먼저 구현한다. 새 메시지·대기열·승인 재개·재접속을 검증한다. 편집·재생성·포크가 활성 목표의 결과를 바꾸는 경우 먼저 목표를 일시정지한다. 포크에는 목표와 미처리 지시를 자동 복사하지 않는다.

경로별 권한과 호환성

기본 런타임과 선택형 사전 준비 런타임을 각각 시험한다. 동등하게 처리할 수 없는 경로는 지원 범위와 사유를 반환한다. 초기 Agent API·트리거·워크플로·자식에서 들어오는 목표 생성 또는 Steer 요청도 명시적으로 거절한다. 기존 실행 요청의 동작은 회귀 테스트로 확인한다.

03

일반 채팅의 AG-UI 1.0 전환

대화를 시작하거나 승인에 답하면 몰디 워커가 한 번 실행한다. 브라우저는 그 결과를 AG-UI로 받는다. “국내 업체만 조사해줘”처럼 이미 일하는 에이전트에게 보내는 지시는 몰디가 해당 실행에 전달한다. 사용자는 같은 대화에서 지시의 접수와 실제 반영을 구분해 본다.

무엇을 바꿀 것인가

현재 기본 화면은 assistant-ui 위에서 LangGraph v3용 명령과 몰디 SSE를 사용한다. 기존 AG-UI GET은 이미 있는 실행을 읽는다. 이전 실험에서 이 변환기가 만든 11개 이벤트는 각각 유효했지만, 첫 이벤트가 CUSTOM이어서 공식 클라이언트가 스트림을 거부했다. 반면 공식 React·Python 어댑터를 연결한 별도 실험에서는 텍스트와 승인 왕복이 동작했다.

권고안　서버에서 권한과 실행을 확정한 뒤 저장 이벤트를 AG-UI 공개 이벤트로 직접 변환한다. 화면은 useAgUiRuntime에 연결한다. 이행 기간에는 같은 실행 기록을 두 형식으로 읽어 결과를 비교한다. 공식 Python 어댑터는 표준 출력과 대조하는 기준으로 활용한다. 그래프를 실행하는 FastAPI 예제를 몰디 워커 옆에 하나 더 붙이면 모델·도구가 두 번 실행될 수 있다.

화면에서 한 행동을 누가 처리하는가

사용자 행동제안하는 요청·응답서버에서 보장할 동작
새 메시지 보내기대화별 POST …/ag-ui/runs에 RunAgentInput을 보낸다. 시작한 실행의 메시지·도구·종료 결과를 SSE로 받는다.조직·대화 권한과 첨부 ID를 확인하고 공개 runId를 서버 실행과 연결한다. 같은 요청·본문의 재전송은 같은 실행으로 연결하고 본문이 달라지면 충돌로 돌려준다. 양쪽의 protocolVersion을 확인한다. 큐에만 접수한 입력은 대기 상태로 표시한다.
승인·거절·질문에 답하기표준 interrupt 결과를 받은 뒤 같은 threadId에 새 runId와 resume[]를 보낸다. 브라우저에서 수행한 도구의 결과는 별도 도구 메시지로 보낸다.서버 체크포인트와 모든 미결 승인 ID, 대상 도구·주체·만료를 대조한다. 두 탭에서 답하거나 재전송해도 승인된 외부 호출은 한 번이다. 사용자가 보낸 이력·도구 정의가 서버 권한이나 승인 상태를 덮어쓸 수 없게 한다.
지금 하는 일에 보충 지시F02의 POST …/runs/{run_id}/steers로 보낸다. ‘접수’는 서버 저장 뒤, ‘반영’은 지시 ID가 대상 모델 입력에 들어간 것을 확인한 뒤 표시한다. 기존 ‘다음 요청’·‘중단 후 실행’도 그대로 선택할 수 있다.요청 키와 순번을 저장하고 다음 모델 호출 직전 abefore_model에서 기존 도구 결과 뒤에 한 번 적용한다. 체크포인트와 접수 기록을 대조해 중복 반영을 막는다. 먼저 끝난 루트 실행의 미전달분은 한 번만 큐로 이월한다.
특정 자식 보기·지시·중지F04의 진행과 결과는 SUBAGENT_*와 subagentRunId로 보낸다. 개별 지시·취소는 선택한 자식 작업에 대한 몰디 명령이다.서버에 자식 작업 ID, 호출별 ID, 부모 도구 호출 ID와 체크포인트를 연결한다. 같은 역할의 자식 둘도 구별한다. 승인 중에 온 지시는 보관한다. 지시 접수 직후 승인이 발생할 수도 있으므로 전달 직전에 미결 승인과 권한을 다시 검사한다. 끝난 자식의 지시를 형제나 부모에게 넘기지 않는다.
부모 응답 뒤에도 별도 작업 계속F05는 자식 대화와 독립 실행을 만들고 parentRunId로 연결한다. 부모가 끝난 뒤에는 자식의 스트림·작업 목록·알림에서 이어 본다.일반 대화의 활성 실행 한 개 제약을 보존한다. 부모 안의 자식은 정상 종료 전에 닫고, 독립 작업의 승인·비용·취소·알림은 자식 단위로 처리한다. 위임 요청 재전송으로 자식이나 알림을 추가 생성하지 않는다.
새로고침·화면 이탈·명시적 중지복귀하면 서버 이력과 조회 전용 구독을 연다. 명시적인 ‘중지’만 기존 서버 취소 명령을 호출하고 실제 종료 결과를 받는다.단순 연결 종료는 구독만 해제한다. 두 번째 탭에서 복귀해도 모델 호출 수가 늘지 않아야 한다. 서버가 정상적으로 취소한 실행은 RUN_FINISHED의 cancelled로 표시한다.

같은 실행에 지시를 넣는 방법

LangChain의 모델 호출 전 훅을 재사용한다. 몰디도 사용 한도 검사에 이 훅을 쓴다. 이번 격리 실험에서 최상위 실행 한 번에 모델이 두 번 호출됐다. 도구 실행 도중 외부에서 보낸 지시는 두 번째 모델 입력에 한 번 들어갔고 기존 도구 결과도 남았다. 같은 역할의 자식 둘을 병렬로 실행한 별도 실험에서는 지정한 자식에만 지시가 한 번 들어갔다. 두 실험 모두 몰디 고정 버전(Deep Agents 0.7.32)과 최신 버전(0.7.42)에서 같은 결과를 냈다.

실험은 결정적 테스트 모델과 메모리 저장소를 사용했다. 훅의 전체 체크포인트 경로는 단계마다 바뀌었다. 위임 시점에 몰디 작업 ID와 부모 도구 호출 ID를 묶고 자식 훅에 전달한다. 최신판은 위임 도구 호출 ID를 훅의 메타데이터로 보냈지만 고정판 실험에서는 보이지 않아, 고정판에서는 명시적으로 전달해야 한다. PostgreSQL 저장 직전·직후에 프로세스를 종료한 뒤에도 ‘반영’ 기록이 실제 입력과 일치하는지는 별도 통과 기준이다.

Deep Agents의 update_async_task도 검토했다. Agent Protocol 서버의 같은 자식 스레드에 새 실행을 만드는 기능이며, 대기 중인 승인 요청을 잃을 수 있다. 부모에 귀속된 자식의 F04에는 호출 전 훅을 쓰고, F05에는 몰디의 대화 워커를 재사용한다. 사전 준비 런타임은 현재 비동기 자식 정의를 거절하므로 두 런타임의 전달·승인 동등성을 따로 검증한다.

탭을 다시 열었을 때의 복원

현재 몰디는 브로커에 먼저 전송하고 비동기로 DB에 저장한다. 화면이 본 마지막 토큰이 DB에 남았다고 가정하면 워커 장애 때 문장이 빠질 수 있다. 조회용 스냅샷에는 대화 분기, 공개 메시지 ID, 미결 승인, 자식과 부모 도구의 연결, 그리고 DB에 연속으로 저장된 마지막 위치를 함께 담는다. 복구 커서는 실행·변환 버전·원본 이벤트와 변환된 프레임의 순번을 식별한다.

처음 연결하는 표준 파서에는 실행 시작부터 유효한 이벤트 순서를 공급한다. 새로고침 시 몰디 이력 어댑터가 저장된 화면과 진행 중인 실행을 복구한다. 중간 프레임만 남았거나 저장 위치가 끊겼으면 서버의 확정 상태부터 다시 구성한다. 브라우저가 먼저 본 미확정 출력은 확정 기록과 대조한다. 이전 분기의 출력과 새 분기의 출력을 섞지 않는다.

assistant-ui의 connect() 또는 이력 어댑터의 resume()를 조회 전용 경로에 연결한다. 둘 다 없을 때 복귀 옵션을 켜면 새 실행을 시작할 수 있다. 자식 메시지는 SDK에서 재로딩 후 평평하게 보일 수 있어, 저장한 부모 도구 호출 ID로 몰디 패널을 복원한다. 대기열은 서버 큐 하나로 관리한다. 이미 전달된 메시지는 서버 ID로 병합하고, 이력 보관 기간이 지난 대화는 남아 있는 공개 메시지로 복원한다.

현재 발행과 저장 순서대화 재생 시 순번 재계산현재 체크포인트와 이력 조회표준 HTTP/SSE의 복구 범위assistant-ui의 자식 이력읽기 전용 재접속 어댑터

F09한국어 장기 기억의 검색 품질

개발 티켓

  2. F09-2
    백그라운드 비교에서 실제 선택 목록의 recall@10, 무관 질문 배제율, 추가 토큰, p95 시간을 기록한다. 승인된 임베딩 제공자만 사용하고 사용자 응답은 기존 방식으로 유지한다.
  3. F09-3
    조직별 비교 시험에는 품질 평가를 통과한 모델과 기준값만 쓴다. 외부 색인 도입 시 원장에서 접근·삭제·승인 상태를 최종 확인하고, 색인 지연 또는 장애에는 기존 키워드 경로를 사용한다.

합격 시나리오
